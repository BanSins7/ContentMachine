## Taxonomy Builder — настройка Pipeline и тесты в самом продукте

После подтверждения анкеты можно прямо в ContentMachine выбирать любую доступную OpenRouter-модель для Fact Extraction, Taxonomy Generation и Critic, изменять версии промптов, reasoning, temperature и токены, сохранять/утверждать конфигурации и проводить повторяемые тесты **вручную** через смету, отдельное согласие на бюджет и пошаговый запуск. Новые шаблоны включают **MiMo Flash → Claude Opus 5.5 → Opus 5.5** с Critic max output **8 000**; **Gemini 4 Argon остаётся в списке для добровольного выбора**.

В интерфейсе доступны результаты прошедших/ошибочных этапов, безопасная диагностика OpenRouter, редактирование категорий после Critic, история PostgreSQL, сравнение количества фактов/категорий/замечаний, экспорт run JSON и новый эксперимент только с новой сметой и новым бюджетом. Автоматические платные повторы отключены; публикация в SRE — только после явного утверждения человеком.

**Пошаговая инструкция:** [Test Studio и Pipeline из интерфейса](docs/TAXONOMY_BUILDER_IN_PRODUCT_TESTS.md). Существующие описания «блоков 2–6» ниже — исторические этапы разработки; текст об отсутствующих будущих этапах в этих секциях не относится к текущему Draft PR #7.

## Новый проект (анкета-заглушка)

В сайдбаре кнопка **«+ Новый проект»** запускает мастер из **9 последовательных шагов**: ниша, цель, описание собственного продукта, ссылка, конкуренты, соцсети конкурентов, аккаунты продвигающих блогеров, референсы успешных видео и загрузка готовых исследований. Название проекта можно дополнительно указать на первом шаге.

Все текстовые поля необязательны, можно вводить текст и URL. Переходы — «Подтвердить и продолжить» / «Назад». Черновик текста сохраняется в браузере; выбранные файлы при перезагрузке страницы нужно выбрать снова.

Доступны PDF/Word/Excel/PowerPoint/TXT/CSV/изображения: до 10 файлов, 10 МиБ каждый, не более 24 МиБ суммарно. Создание проекта **сохраняет данные и сами документы на компьютере, вне Git-клона**:

- Windows: `%LOCALAPPDATA%\ContentMachineData\projects\<project-id>\`
- macOS/Linux: `~/.contentmachine/projects/<project-id>/`

Путь можно изменить через `CM_PROJECTS_DIR`. Сохранённые проекты показываются в левом меню и на странице «Мои проекты». Это только локальная анкета-заглушка: она **не запускает** Discovery, внешние API, видеозагрузку, ИИ-анализ или производство роликов, и пока не связана с PostgreSQL D1.



### Taxonomy Builder — блок 6: настоящий запуск и Human Review

После подтверждения анкеты, Pipeline и бюджета можно создать запуск Taxonomy Builder. Каждый вызов OpenRouter инициируется вручную: Fact Extraction → проверка/редактирование извлечённых фактов человеком → Taxonomy Generation → опциональный Critic → проверка/утверждение категорий. Исходные цитаты и связи тем с фактами проверяются сервером, а утверждённая таксономия сохраняется неизменяемой версией в PostgreSQL.

Перед платным запросом резервируется консервативная стоимость; реальный `usage.cost` фиксируется. При сетевой неопределённости попытка не повторяется автоматически. Локальное приложение использует ключ, уже заданный в его настройках, либо `OPENROUTER_API_KEY`. Реальные LLM-тесты выполняются **отдельно от обычного CI**. Один реальный запрос к `deepseek/deepseek-v4.1-flash` успешно проверил Fact Extraction и точные исходные цитаты; OpenRouter списал **$0.000048472**. Общий разрешённый лимит **$0.60**, одноразовый live-workflow после теста отключён. Документы пока не передаются LLM, как и в смете блока 5.

Подробнее: [docs/TAXONOMY_BUILDER_BLOCK6_RUNNER_V1.md](docs/TAXONOMY_BUILDER_BLOCK6_RUNNER_V1.md).

### Taxonomy Builder — блок 5: смета и согласие с бюджетом

После утверждения Pipeline интерфейс открывает отдельный экран **примерной стоимости**. Расчёт делается локально, без вызовов LLM, по **проверенным OpenRouter тарифам в USD за один токен**, зафиксированному списку моделей и явно описанной эвристике токенов. Показываются низкий, ожидаемый и повышенный сценарии, стоимость каждого включённого этапа, reasoning, источник/время проверки цены и исключённые расходы. Повышенная оценка **не является гарантированным потолком**.

Можно вернуться в Pipeline Studio, сменить модель/reasoning/temperature и получить новую смету, затем отдельно разрешить будущие затраты до выбранного лимита либо отказаться. Согласие можно отозвать; оно не списывает средства и не запускает ИИ. Смета истекает, а тарифы/снимки проверяются снова перед разрешением бюджета. Если в проекте есть документы, они исключены из текущей оценки и требуют явного предупреждения.

API: GET `/api/projects/{id}/taxonomy-builder/cost`, POST `.../cost/quote`, `.../cost/consent`, `.../cost/revoke`. PostgreSQL миграция `006_tb_cost_quotes_and_consents.sql`. Реальные платные запросы, лимиты фактического расхода и run orchestration появятся только в **блоке 6**.

Документация: [docs/TAXONOMY_BUILDER_BLOCK5_COST_V1.md](docs/TAXONOMY_BUILDER_BLOCK5_COST_V1.md).

### Taxonomy Builder — блок 4: Pipeline Studio UI

После подтверждения анкеты открывается **Taxonomy Pipeline Studio** — отдельный адаптивный редактор этапов с выбором моделей, reasoning, temperature и max tokens. Каталог обновляется по явному запросу из OpenRouter; недоступные модели не подменяются фиктивными. Работают сохранение черновика, утверждение версии и история. **Смета, платный запуск и реальный LLM ещё не реализованы.**

Документация: [docs/TAXONOMY_BUILDER_BLOCK4_STUDIO_V1.md](docs/TAXONOMY_BUILDER_BLOCK4_STUDIO_V1.md).

### Taxonomy Builder — блок 3: Model Registry и Pipeline backend

Каталог включает 12 моделей, выбранных пользователем (OpenAI, Google, Anthropic, DeepSeek, Z.ai, Xiaomi, Qwen). Возможности и цены **не выдумываются**: они считываются по явному запросу из публичного каталога OpenRouter и сохраняются версионно в PostgreSQL. Точные параметры `reasoning`, `temperature` и `max_output_tokens` проверяются для каждого этапа.

Реализованы `GET /api/projects/{id}/taxonomy-builder/models`, `GET /api/projects/{id}/taxonomy-builder/pipeline`, `POST /api/taxonomy-builder/models/refresh`, `POST .../pipeline/draft` и `POST .../pipeline/approve`. Только после подтверждённой анкеты можно сохранить/утвердить настройки. Запросы к LLM, сметы и визуальные настройки будут позже. Полный контракт: [docs/TAXONOMY_BUILDER_BLOCK3_PIPELINE_V1.md](docs/TAXONOMY_BUILDER_BLOCK3_PIPELINE_V1.md).

### Taxonomy Builder — блок 2: подтверждение анкеты и переход в Pipeline Studio

После создания или редактирования проекта открывается экран **«Проверь данные проекта»**. Для Taxonomy Builder v1 обязательны ниша Health & Fitness, тип продукта, проблемы аудитории, а также реальные функции продукта (кроме типа «Нет продукта»). Необязательные поля анкеты можно оставить незаполненными в локальном черновике.

При подключённой PostgreSQL и применённой миграции `004_tb_intake_confirmations.sql` можно нажать **«Подтвердить анкету»**: подтвердится ровно сохранённая ревизия и SHA-256 снимка анкеты. При последующем редактировании проект требует нового подтверждения; предыдущая версия остаётся в истории.

После подтверждения откроется **Taxonomy Pipeline Studio — подготовительный экран**. Редактор моделей, reasoning, temperature, утверждение Pipeline, расчёт стоимости и запуск LLM будут добавляться **только в блоках 3–6**. Сейчас платные запросы и создание таксономии не выполняются.

HTTP:
- `GET /api/projects/{id}/taxonomy-builder/intake` — актуальный профиль, список недостающих данных, статус БД и подтверждения.
- `POST /api/projects/{id}/taxonomy-builder/intake/confirm` с `{"expected_revision": 1, "expected_hash":"<sha256>"}` — атомарное идемпотентное подтверждение; для POST обязателен `X-ContentMachine: 1`.
- При выключенной БД проект сохраняется локально, но **кнопка подтверждения блокируется**. Для включения требуется `CM_DB_ENABLED=1`, корректное подключение и `python -m intelligence.migrate`.

Подробности: [docs/TAXONOMY_BUILDER_BLOCK2_INTEGRATION_V1.md](docs/TAXONOMY_BUILDER_BLOCK2_INTEGRATION_V1.md).

## Подготовка к Research Taxonomy Builder

Мастер создания проекта по-прежнему состоит из **9 шагов** и сохраняет исходные поля, ссылки на конкурентов, видеореференсы и документы. На третьем шаге теперь отдельно указываются **тип продукта**, **его реальные функции** и **проблемы аудитории** (все поля необязательны; описание сохранено).

Проект можно **редактировать** из карточки. Изменения сохраняются локально атомарно, `profile_revision` увеличивается только при фактическом изменении, устаревшая версия возвращает HTTP 409. Уже прикреплённые документы сохраняются; добавление/замена вложений через редактирование пока не поддерживается.

Для будущего Builder предусмотрен **стабильный машинный вход**:

- `GET /api/projects/<id>/taxonomy-input` — исходная анкета, список документов, `project_id`, версия, SHA-256 профиля, пробелы в структурированных полях и статус синхронизации БД.
- `POST /api/projects/<id>/update` — изменяет поля проекта при передаче `expected_revision`, обязательный заголовок `X-ContentMachine: 1`.
- В PostgreSQL миграция `003_taxonomy_intake.sql` создаёт `project_registry` и **неизменяемые** `project_profile_versions`. Реестр заполняется при создании, редактировании или запросе taxonomy-input, когда включён PostgreSQL.

При выключенной БД анкета продолжает работать как раньше; `profile_db_sync=disabled`, а при временной ошибке — `unavailable`. Перед настоящим запуском Builder нужно проверить `profile_db_sync=synced`; файл проекта остаётся локальным источником истины, документы в PostgreSQL не копируются.

**Подробный контракт:** [docs/TAXONOMY_BUILDER_INTAKE_CONTRACT_V1.md](docs/TAXONOMY_BUILDER_INTAKE_CONTRACT_V1.md). Этот шаг **не запускает LLM**, не строит исследовательскую таксономию и не меняет работу Discovery/Downloader.


# ContentMachine — Instagram, TikTok & YouTube Downloaders

Локальный минималистичный сайт: **три** инструмента в сайдбаре (Instagram Downloader, TikTok Downloader, YouTube Downloader). На каждой вкладке две метрики, одна строка для ссылки, кнопки «Найти» и «Скачать», прогресс и ошибки. У каждого инструмента отдельный счётчик видео; расходы OpenRouter локально учитываются по платформам. Не нужны Node.js и отдельный хостинг.

## Установка Windows (один раз)

1. Скачайте `INSTALL_CONTENTMACHINE_ONCE.bat` из репозитория, запустите его двойным кликом.
2. Если Git отсутствует, установщик попробует поставить его через `winget` (если это не удалось — установите [Git for Windows](https://git-scm.com/download/win) и повторите запуск).
3. Поскольку репозиторий **приватный**, Git Credential Manager может один раз попросить войти в GitHub через браузер. Это нужно для последующих обновлений.
4. Установщик клонирует репозиторий в `%LOCALAPPDATA%\ContentMachine`, перенесёт локальный OpenRouter-ключ из старой папки в `Downloads` (если найдёт) и добавит автозапуск при входе в Windows.
5. Откройте сайт `http://127.0.0.1:8765` — установщик открывает его автоматически.

После установки компьютер проверяет ветку `main` в GitHub каждые **60 секунд**. Если появились изменения, сервис дождётся окончания скачиваний/распознавания, безопасно обновит код и перезапустится. Чтобы увидеть изменения дизайна, достаточно нажать **F5**. Не нужно снова скачивать ZIP или менять файлы вручную. Для новой версии зависимостей `pip` запускается автоматически. Автообновление работает, пока запущен локальный процесс; при входе в Windows он стартует через папку автозагрузки.

Старую версию, которая занимает порт 8765, нужно **закрыть** перед первой установкой. Если GitHub недоступен, локальная установленная версия продолжает работать. При локальных изменениях отслеживаемых файлов обновление приостанавливается и не перезаписывает их.

## Использование

В Instagram Downloader вставьте ссылку на Instagram-профиль или один Reels → **Найти** → **Скачать**. Профили могут требовать авторизацию/не отдавать список публикаций: в этом случае интерфейс покажет ошибку. Видео и субтитры Instagram сохраняются в `~/Downloads/InstagramArchive/` с единым shortcode для MP4, SRT, TXT, JSON, общим `index.csv`.

В TikTok Downloader вставьте прямую ссылку на публикацию вида `https://www.tiktok.com/@username/video/7380123456789012345` или на профиль `https://www.tiktok.com/@username`. Ссылка проверяется по ID ролика перед загрузкой; для профиля производится попытка получить список открытых публикаций (TikTok может ограничивать перечисление и загрузку). Результаты сохраняются отдельно в `~/Downloads/TikTokArchive/<username>/` — одноимённые MP4, SRT, TXT и JSON. TikTok использует тот же OpenRouter и резервный локальный Whisper, язык определяется автоматически.

Мини-аналитика показывает количество скачанных видео и **локально учтённые расходы OpenRouter** (это не фактический баланс провайдера). Если ключ не нашёлся при миграции, его можно локально записать в `worker/openrouter_key.txt`; файл исключён из Git через `.gitignore`. Никогда не требуется публиковать ключ в репозитории.

## Проверка

`python -m unittest discover -s tests -v` и `node --check site/app.js`.

Архитектура: Python HTTP-server (только `127.0.0.1`), yt-dlp, faster-whisper/OpenRouter, HTML/CSS/JS. YouTube Shorts Downloader планируется следующим модулем. Проверки GitHub Actions запускают `unittest`, `compileall` и `node --check` после каждого обновления.

## YouTube Downloader — встроенный модуль Shorts

Интегрирован функциональный конвейер из пользовательского архива **Content Zavod Shorts v0.1.10** в общий локальный сервер (отдельное Chrome-расширение и второй сервер на порту 8765 не требуются).

- Поддерживаются ссылки `https://www.youtube.com/shorts/VIDEO_ID`, `https://youtu.be/VIDEO_ID`, `watch?v=VIDEO_ID` и `youtube.com/@канал` (сканирование раздела Shorts, максимум 500 роликов за поиск).
- По умолчанию доступ без авторизации; для Shorts с проверкой доступа можно **явно выбрать** Chrome, Edge, Brave или Firefox на странице YouTube Downloader. Данные сессии остаются на ноутбуке.
- После «Найти» → «Скачать» загрузчик проверяет точный ID публикации **до записи видео**, проверяет наличие видеодорожки и звука, а затем сохраняет файлы в `~/Downloads/YouTubeArchive/single/VIDEO_ID/`.
- Файлы: `video.mp4`, `subtitles.srt`, `transcript.txt`, `metadata.json`. MP4 не содержит новых наложенных субтитров; SRT/TXT сохраняются отдельно.
- Субтитры создаёт общий OpenRouter MAI-Transcribe 2 через уже подключённый ключ и общую статистику расходов. При ошибке API используется локальный Whisper; если распознавание не удалось, MP4 сохраняется, а ошибка транскрибации записывается в JSON. YouTube caption API не запрашивается, как в версии Shorts v0.1.10.
- Видео YouTube не смешиваются с Instagram/TikTok; отдельная мини-аналитика показывается при выборе третьей вкладки.

### Ограничения

YouTube может требовать вход или отказывать в скачивании. Авторизация браузером — опциональная и не гарантирует доступ. На Windows Chrome иногда блокирует чтение cookies: попробуйте Firefox, если получите соответствующее предупреждение. Массовую загрузку большого канала сначала проверьте на одном видео. Архив с исходным Shorts-модулем содержит API-ключ — **не загружайте исходный ZIP в GitHub**. В ContentMachine используется уже существующий локальный `worker/openrouter_key.txt`.

Для проверки: `python -m unittest discover -s tests -v`.


## Дополнительные параметры YouTube Downloader (перенесены из popup v0.1.10)

В разделе YouTube появились настройки расширения: **максимум Shorts** (5, 20, 50, 100, все доступные до 500 за поиск), **язык речи** (авто, русский, английский), **получение субтитров** (MAI через OpenRouter, локальный Whisper, выключено) и **авторизация** (без входа, Chrome, Edge, Firefox, Brave). Настройки запоминаются локально в браузере.

После запуска доступны **Остановить**, **Открыть папку с файлами**, счётчики скачанных/пропущенных/ошибок/отменённых заданий и краткий журнал по роликам. Отмена производится безопасно — запрос к YouTube или модели, уже находящийся в обработке, может завершиться до остановки. Права на чтение cookies браузера используются только после явного выбора браузера. Скачанный MP4 можно повторно обработать с новым языком или способом распознавания без повторной загрузки.

## Параметры → единый OpenRouter API-ключ

В нижней части левого сайдбара находится **Параметры**. Там можно вставить новый API-ключ OpenRouter и нажать **Сохранить ключ**. Он сразу станет основным для **Instagram Downloader, TikTok Downloader и YouTube Downloader** при следующих запросах распознавания речи — перезапуск не требуется. При смене ключа текущая сессия скачивания не прерывается; запросы, уже отправленные OpenRouter, могут завершиться со старым ключом.

Сайт хранит один файл \`worker/openrouter_key.txt\` в локальном каталоге установленного ContentMachine (в \`.gitignore\`). Этот файл уже использовался прежними версиями, поэтому существующий ключ сохраняется при обновлении. **Переменная окружения \`OPENROUTER_API_KEY\` больше не имеет приоритета**: управлять ключом нужно через Параметры. Ключ не возвращается в ответах API, не подставляется обратно в HTML, не сохраняется в \`localStorage\` и не отправляется в GitHub; в UI отображается только статус «Ключ подключён» / «Ключ не задан».

Примечание: общий счётчик расходов OpenRouter хранится отдельно от ключа в \`worker/openrouter_usage.json\`. Замена API-ключа не обнуляет локальную историю расходов. Для сохранения настроек используется существующий локальный API \`POST /api/key\` с проверкой Host/Origin и заголовка \`X-ContentMachine\`.


Для просмотра уже сохранённого ключа используйте в «Параметрах» кнопку **«Открыть сохранённый ключ»**: Windows откроет локальный файл в Блокноте. Сайт намеренно не передаёт содержимое ключа в браузер, поэтому текст в пустой строке ввода — подсказка для **нового** ключа, а не значение текущего. Кнопка «Показать» работает только для текста, введённого в форму. Это не мешает централизованной смене ключа для всех модулей.

## ContentMachine Intelligence — блок 1: PostgreSQL

Добавлена **неразрушающая** инфраструктура под будущие Discovery, Analytics, Batches и AI. Существующие Instagram/TikTok/YouTube загрузчики не зависят от PostgreSQL и работают даже до настройки базы.

**Windows, один раз:**

1. Установите и запустите Docker Desktop (Windows с WSL2 backend). Убедитесь, что Docker работает.
2. Дождитесь автообновления ContentMachine из GitHub или выполните `git pull` в локальной папке проекта.
3. Запустите из папки проекта `SETUP_POSTGRES_WINDOWS.bat`.
4. Откройте `http://127.0.0.1:8765/api/intelligence/health` — в ответе должно быть `"database": "connected"`.

Установщик сгенерирует приватный **.env** (исключён из Git), развернёт PostgreSQL 17 в Docker с сохранением данных в Docker volume, открывая порт **только на 127.0.0.1:54329**, установит psycopg и применит миграции. Он не перезаписывает уже созданный пароль. Никогда не загружайте файл `.env` в GitHub. Docker и база не запускаются скрытно обычным автообновлением кода.

**Диагностика:** `python -m intelligence.health`. **Повтор миграций:** `python -m intelligence.migrate`. **Остановка контейнера без удаления данных:** `docker compose stop`. **Просмотр:** `docker compose ps`.

В БД предусмотрены `sources`, `topics`, `creators`, `videos`, `search_queries`, `discoveries`, `metric_snapshots`, `jobs`, `analytics_scores`, `batches`, `batch_videos`, `media_assets`, `video_analyses`, `audit_events`. Время метрик сохраняется отдельно; неизвестные реакции — `NULL`. У каждого источника есть правила доступа и хранения (права на новые действия изначально выключены). Медиа хранятся на диске, не в БД.

Очередь `intelligence.jobs` поддерживает идемпотентное создание задач, атомарную выдачу нескольким воркерам (`FOR UPDATE SKIP LOCKED`), leases, retries и восстановление просроченных задач. **Сборщики платформ и LLM-процессы появятся в следующих блоках:** сейчас нет фонового скрейпинга, скачивания чужих видео или запуска GPU-моделей.

Для будущих функций: все источники должны учитывать права на хранение, производные метрики и доступ к видео. Наличие записи в базе само по себе не означает право использовать её для любого вида анализа.


## GitHub Desktop + RUN_AUTO.bat (один checkout)

GitHub Desktop: **Fetch** проверяет удалённые изменения, **Pull** переносит их в локальные файлы. Когда `RUN_AUTO.bat` запущен в этой же папке, он самостоятельно проверяет GitHub примерно раз в 60 секунд, ставит обновления, автоматически выполняет новые миграции PostgreSQL и перезапускает веб-сервер. Если GitHub Desktop сделал Pull раньше, наблюдатель теперь также обнаруживает новое локальное HEAD и перезапускает сервер при отсутствии активных заданий. После обновления сайта обычно нужен `Ctrl+F5`.

**Две папки — два независимых checkout**. Если GitHub Desktop клонирован в другое место, а автозапуск Windows использует `%LOCALAPPDATA%\\ContentMachine\\RUN_AUTO.bat`, обновление одной папки не меняет другую. Запустите `CHECK_CONTENTMACHINE_WINDOWS.bat` в папке GitHub Desktop: он показывает пути, короткие commit SHA, Docker status и безопасные HTTP-статусы. Не отправляйте файлы `.env` и ключи API.

При первой установке либо после истечения учётных данных Git Credential Manager может открыть GitHub OAuth-login в браузере: приватному репозиторию требуется аутентификация. Возврат на временный `127.0.0.1` с `code` и `state` — штатная схема loopback callback; подобные адреса нельзя публиковать или использовать повторно. У GitHub Desktop и Git CLI могут быть разные способы хранения учётных данных.
