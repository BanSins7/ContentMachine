# TikTok Carousel Studio

Отдельная студия Content Machine на **React 19 + TypeScript + Vite**.
Встроена в существующий Python-сервер, работает локально по
`http://127.0.0.1:8765/carousel-studio/`.

## Быстрый запуск на Windows

Из PowerShell на компьютере с установленным ContentMachine:

```powershell
cd C:\ContentMachine
git status
git fetch origin feature/rtb-market-intelligence-20261030
git switch feature/rtb-market-intelligence-20261030
git pull --ff-only origin feature/rtb-market-intelligence-20261030
powershell -ExecutionPolicy Bypass -File .\RUN_CAROUSEL_STUDIO.ps1
```

Если `git status` показывает незавершённый merge или конфликт, сначала
завершите его в своей рабочей копии. Не выполняйте `git reset --hard` ради
запуска Studio. Если ветка ещё не создана локально, после `git fetch` вместо
`git switch` используйте
`git switch --track origin/feature/rtb-market-intelligence-20261030`.

Перед запуском обновлённой версии **остановите старый `python app.py`**
через Ctrl+C в его окне. Если старый сервер продолжает слушать порт 8765,
launcher не должен использовать старый Python backend с новым интерфейсом.
Новая версия проверяет поддержку лимита перед платным запуском.

Если PowerShell блокирует локальные скрипты:
```powershell
powershell -ExecutionPolicy Bypass -File .\RUN_CAROUSEL_STUDIO.ps1
```

Команда собирает React-приложение, проверяет Python-библиотеки, запускает
backend при необходимости и открывает Studio. После обновления Python-кода
обязательно перезапускайте backend; обновление страницы не загружает новый
код Python в старый процесс.

## Настройки API-ключей в интерфейсе

В левом меню TikTok Carousel Studio выберите **«Настройки»**.
На странице есть переключатель **OpenRouter / Rus-GPT** и отдельные поля
**OpenRouter API Key**, **Rus-GPT API Key** и **Bright Data API Token**.
Для Rus-GPT выбирается именно `anthropic/claude-haiku-5.5` через
`https://rus-gpt.com/api/v1/chat/completions`, а не другая модель.
Для OpenRouter остаётся `google/gemini-3.8-flash`.
Вставьте ключ выбранного LLM-провайдера и Bright Data, подтвердите право
на сбор публичных данных и нажмите **«Сохранить настройки»**.

- У Rus-GPT на 03.11.2026 опубликована стоимость **60 ₽ / 1 млн входных**
  и **300 ₽ / 1 млн выходных токенов** для Claude Haiku 5.5
  ([официальный список моделей](https://rus-gpt.com/models)).
- Выбор провайдера и точная модель записываются в SQLite в момент создания
  каждого запуска. Смена переключателя влияет только на **новые** запуски;
  незавершённая задача продолжается на прежнем провайдере, без скрытого
  переключения при недостатке баланса.
- Токены и расчётная стоимость Haiku учитываются в **рублях**,
  OpenRouter Gemini — в **долларах**. Статистика одной валюты не суммируется
  с другой, а отсутствие токенов/счёта не интерпретируется как нулевая цена.
- API Rus-GPT поддерживает мультимодальные изображения через совместимый
  с OpenAI `chat/completions`
  ([документация](https://rus-gpt.com/instructions/chat)).
  При HTTP 402 сохраняются результаты и запуск останавливается до нажатия
  «Продолжить». Подтверждение успешного живого вызова со списанием требует
  запуска с собственным ключом; офлайн тесты не проверяют реальный биллинг.

- Ключи всех трёх сервисов шифруются Windows DPAPI для текущего Windows-пользователя в
  `marketing-qa/carousel-studio/studio-credentials.dpapi` и не сохраняются
  в браузер, SQLite или результаты JSON/ZIP. Файл находится в исключённой
  из Git папке `marketing-qa/` и никогда не должен попадать в репозиторий.
- `GET /api/studio/settings` возвращает только признаки настройки и
  разрешений; API-ключи даже частично не возвращаются.
- Пустое поле при сохранении означает **оставить ранее записанный ключ**.
  Вставка нового ключа заменяет старый локальный ключ.
- Настройки Studio имеют приоритет над существующими ключами из
  `.env` / переменных окружения. Если в Studio ключ не записан,
  работают старые способы конфигурации.
- Сохранение ключей не делает платных API-вызовов и не проверяет баланс.
  Индикатор «Готов к сбору» означает **локально настроенный доступ**,
  а не успешное соединение с Bright Data.
- В частности, Bright Data продолжает требовать явного подтверждения прав
  на сбор данных. Флажок в настройках заменяет только две прежние
  серверные настройки `CM_BRIGHTDATA_METRICS_ENABLED=1` и
  `CM_BRIGHTDATA_METRICS_RIGHTS_VERIFIED=1`; если они уже настроены
  через `.env`, значения продолжают работать.
- Шифрованный файл привязан к Windows-пользователю и не будет
  расшифровываться на другом ПК или под другой учётной записью.
  В таком случае ключи нужно ввести заново в настройках.

## Возможности

- **Ссылка**: только реальная TikTok photo carousel (`/@handle/photo/id`).
- **Аккаунт**: Bright Data получает снимок доступных публикаций профиля,
  затем Studio анализирует **не более указанного лимита каруселей**
  (по умолчанию 30; допустимо от 1 до 5000). Приоритет имеют публикации
  с наиболее поздней достоверной датой в ответе Bright Data; при отсутствии
  дат сохраняется порядок ответа провайдера. Если найдено меньше 30,
  проанализируются только найденные. Это максимум попыток, а не гарантия
  30 успешных анализов.
- Лимит применяется **после** полного сбора снимка профиля: все возвращённые
  обычные видео и карусели остаются в знаменателе статистики аккаунта,
  но дополнительные Bright Data запросы, скачивание и Gemini ограничены
  выбранным количеством каруселей. Оплата Bright Data за снимок профиля
  зависит от **всех** успешно полученных записей, а не от выбранного лимита.
- Фото скачиваются через существующий `gallery-dl`; видео MP4 сознательно
  отбрасываются. Слайды хранятся как реальные изображения с проверкой SHA-256.
- Для каждой выбранной карусели запускается выбранный LLM-провайдер:
  `google/gemini-3.8-flash` через OpenRouter **или**
  `anthropic/claude-haiku-5.5` через Rus-GPT. Оба получают
  **полную карусель как один контекст** и нейтральный промпт,
  без выдумывания техник по обычной позе.
- Bright Data собирает публичные цифры, числовые поля и производные
  отношения к просмотрам. Недоступные retention, watch time или среднее
  время на слайде остаются `null`, не угадываются.
- Обновляемый прогресс/логи, персистентная локальная SQLite, отдельный JSON
  и ZIP с оригиналами и результатами.
- Структурная статистика: 1–2, 3–5, 6–8, 9+ слайдов. В каждой группе
  количество и доля каруселей, медиана просмотров, ER, доля просмотров
  аккаунта и **индекс вклада** (доля просмотров / доля публикаций).
- Вложенные батчи по 10 публикаций, отсортированные по просмотрам от
  наибольших к наименьшим. В каждом батче доступны сравнительные метрики,
  описательные отклонения от медианы группы и переход к Gemini-анализу.
  Блок «Сравнение батча» показывает отношение медианных просмотров и
  взвешенного ER к группе, а также разницу в частоте хуков, CTA и
  интеграций продукта с *остальными* батчами той же длины. Для Gemini
  требуется не менее 3 валидных разметок с каждой стороны, для индекса
  просмотров — 3 наблюдения в батче и 5 в группе, для ER — 3 и 5
  соответственно. Если данных не хватает, показатель будет `null`.
- При запуске по **аккаунту** сохраняются публичные счётчики и обычных
  видео TikTok, чтобы сравнивать вклад каруселей со всем полученным
  снимком аккаунта. Обычные видео не скачиваются и не анализируются Gemini.
- Отдельный `group-analytics.json` доступен в UI, ZIP и SQLite.
  Для проверки знаменателя всех публикаций сохраняется
  `channel-snapshot-public-metrics.json`: публичные счётчики каждого
  возвращённого поста (включая обычные TikTok-видео), без загрузки их медиа.
- **Стоимость Gemini 3.8 Flash:** ориентир OpenRouter Standard на 03.11.2026 —
  $0.75 / 1 млн input-токенов и $3.75 / 1 млн output-токенов
  ([страница модели](https://openrouter.ai/google/gemini-3.8-flash)).
  Это временный тариф со скидкой 50%, который может измениться.
  В `analysis.json` каждой карусели сохраняются `usage.reported_cost_usd`
  (если OpenRouter сообщает стоимость) и
  `usage.estimated_standard_cost_usd` (расчёт по указанному тарифу,
  только если вернулось число токенов). В `full-analysis.json`
  есть `gemini_cost_summary` с суммой **известных** расходов и охватом.
  Неизвестная стоимость не превращается в 0, а оценка не является лимитом.
  Benchmark `scripts/analyze_marketing_carousel_story.py` сохраняет
  собственную прежнюю модель для воспроизводимости старых сравнений.
- В архиве все фото, `manifest.json`, `metrics.json`, `analysis.json`,
  `full-analysis.json`, журнал и JPEG-входы Gemini. Логи можно скачать отдельно.

## Накопительная аналитика TikTok-аккаунтов

В левом меню Studio появилась **«Аккаунты»** — список профилей из локальной
истории. Выберите профиль, чтобы увидеть общее число уникальных каруселей,
историю запусков и накопленную аналитику, затем скачайте единый JSON.
В форме нового анализа также есть выпадающий список ранее введённых аккаунтов.

Для каждого профиля автоматически создаются два локальных файла в папке
marketing-qa/carousel-studio/accounts/<account-id>/:

- **account-master-analysis.json** — все уникальные TikTok ID, анализы LLM,
  метрики, исходный run ID, модель, манифест и пути к сохранённым файлам
- **account-group-analytics.json** — пересчитанные группы и батчи
  **по накопленной выборке** всех локальных запусков этого аккаунта

Генерация полностью локальная: **нет вызовов Bright Data или LLM**.
Общий JSON обновляется после упаковки нового профильного запуска, включая
частичный результат или паузу. Отдельные файлы прежних запусков
сохраняются нетронутыми.

Дедупликация: один TikTok native_id — одна запись. Первый успешно сохранённый
анализ имеет приоритет перед более поздней неуспешной попыткой.
Все ранее сохранённые аккаунты восстанавливаются из той же studio.sqlite3
даже если их анализ был проведён до появления этой функции.

Поле profile_snapshot_history сохраняет снимки статистики аккаунта
раздельно с датами и ID запусков. Для долей просмотров и сравнительных ER
используется **только последний непустой снимок**, без суммирования счётчиков
разных дат. Старые карусели остаются в общем анализе, даже если не найдены
в последнем снимке профиля.

**Открыть библиотеку и скачать JSON — бесплатно.** Выбор ранее сохранённого
профиля лишь заполняет форму, а кнопка **«Запустить анализ»** снова
обращается к Bright Data за новым снимком. Уже успешно проанализированные
карусели пропускаются до дополнительных запросов и вызовов LLM.

Локальные API:
- GET /api/studio/accounts — каталог аккаунтов
- GET /api/studio/accounts/<account-id> — сводка по профилю
- GET /api/studio/accounts/<account-id>/download/json — общий JSON
- GET /api/studio/accounts/<account-id>/download/groups — общие группы

Данные из **другой папки ContentMachine**, в которой используется другая
studio.sqlite3, автоматически не объединяются: сначала требуется
перенести всю соответствующую локальную историю.

## Если Bright Data долго показывает running на 17%

После полного снимка профиля Studio уже содержит исходные публичные
счётчики и зафиксированный в SQLite список выбранных каруселей.
Вторичный запрос Bright Data для уточнения метрик необязателен.
Он ограничен **240 секундами ожидания на один пакет**: если первый пакет
не готов, Studio не создаёт следующий платный пакет и продолжает загрузку
фотографий и вызовы выбранной LLM со статистикой исходного снимка.
В журнале остаётся ID зависшего снимка для проверки у провайдера.
Новые платные запросы автоматически не повторяются.

Для **старого запуска, который уже завис до обновления**:
1. Запомните ID запуска и остановите **только соответствующий сервер**
   `python app.py` (или его окно PowerShell), не запускайте второй сбор
   аккаунта и не удаляйте каталог `marketing-qa/carousel-studio`.
2. Обновите Git-ветку и запустите Studio на том же локальном worktree.
   Сервер пометит старый запуск `interrupted`.
3. Выберите этот запуск в истории и нажмите **«Продолжить анализ»**.
   Продолжение использует сохранённые `studio_targets` и исходные
   метрики из `studio_channel_posts`. Не запускается второй профильный
   снимок или дополнительное уточнение метрик. Уже завершённые LLM
   результаты никогда не отправляются на повторный анализ.

Исходный снимок профиля может содержать меньше числовых полей, чем
подробный ответ отдельного поста. Недоступные поля сохраняются как
отсутствующие; метрики удержания и времени на слайде не выдумываются.
Завершение оставшихся анализов всё ещё требует оплаты LLM.

## Возобновление после нехватки средств и повторный ввод аккаунта

- При ответе выбранного LLM-провайдера (OpenRouter или Rus-GPT) **HTTP 402** текущая карусель получает состояние
  `awaiting_credits`, запуск переходит в `paused` и **дальше не делает
  Gemini-вызовов**. Результаты уже обработанных публикаций, скачанные изображения,
  JSON, SQLite и частичный ZIP сохраняются.
- После пополнения баланса откройте существующий запуск в Studio и нажмите
  **«Продолжить анализ»**. Возобновление использует выбранные и сохранённые в
  SQLite `studio_targets`, без повторного триггера Bright Data. Завершённые
  карусели пропускаются, изображение карусели, остановленной по HTTP 402,
  проверяется по SHA-256 и используется повторно.
- Если повторно ввести username *пока у него есть незавершённый запуск*,
  Studio открывает эту же задачу, без нового платного запуска.
- После завершения задачи можно снова ввести тот же username: Bright Data
  получит **новый снимок профиля** (это отдельная оплата), но все TikTok ID,
  ранее **успешно проанализированные** и сохранённые в SQLite, исключаются
  **до** запроса подробных метрик, загрузки фото и Gemini.
  Лимит «30» применяется к **новым каруселям**, а не к уже обработанным.
  Неуспешные публикации могут быть рассмотрены повторно в будущем запуске.
- Если запрос был прерван в момент отправки Gemini и неизвестно, успел ли
  OpenRouter списать деньги, автоматическое повторение **запрещено**.
  Для такого случая потребуется ручная проверка. Только подтверждённый
  HTTP 402 разрешает безопасный повтор после пополнения.
- Возобновление возможно при сохранённой локальной SQLite, списке
  `studio_targets` и файлах запуска. Одного скачанного ZIP недостаточно,
  чтобы восстановить задачу в новой установке. Не удаляйте локальную папку.
- Дубликаты отслеживаются только в локальной истории текущей Studio.
  Старые публикации из других установок и внешних баз без импорта
  не распознаются автоматически.

## Подключения

Ключи задаются только **на сервере**, никогда в React-форме.
Используются существующие настройки:
`CM_BRIGHTDATA_API_TOKEN`, `CM_BRIGHTDATA_METRICS_ENABLED=1`,
`CM_BRIGHTDATA_METRICS_RIGHTS_VERIFIED=1` и серверный OpenRouter ключ.

**Платные вызовы:** один запуск в UI разрешает необходимые запросы Bright Data
и Gemini. Количество каруселей не ограничено интерфейсом. Фактическое число,
стоимость и охват зависят от провайдера, лимитов аккаунта и количества слайдов.
Bright Data может вернуть не всю историческую ленту TikTok: интерфейс никогда
не считает неполный снимок полным архивом аккаунта.

Вариант с готовым snapshot_id без повторной оплаты источника пока не реализован.
Ошибки сетевого запроса на запуск Bright Data или после запуска Gemini не
повторяются автоматически, чтобы избежать двойного биллинга.

## Разработка

```powershell
python app.py
cd carousel-studio
npm install
npm run dev
```

Vite открывается на `http://127.0.0.1:5173/carousel-studio/`, запросы к
`/api` проксируются на локальный Python. Для production-сборки используйте
`npm run build`, выход находится в `site/carousel-studio/`.

## Ограничения

- Это **самостоятельная локальная SQLite**, а не подключение к основным таблицам
  PostgreSQL Marketing. Результаты каждой карусели хранятся одновременно
  как JSON на диске и в SQLite.
- Снимок профиля может не покрывать все исторические посты TikTok.
  Поэтому проценты вклада считаются только среди возвращённых публикаций.
  Если данные части публикаций недоступны, это отмечается в отчёте.
  Неизвестные просмотры не заменяются нулями. Если в снимке
  доступны просмотры не всех постов, доля известных просмотров
  отображается вместе с охватом; индекс относительного вклада
  скрывается до полного покрытия счётчика просмотров.
  Карточка карусели, не сопоставленная с фотопостом этого же снимка,
  не влияет на расчёт доли и ER аккаунта; её ID попадает в
  `unmatched_profile_item_ids`. Старые JSON без блока `comparison`
  остаются доступными в интерфейсе.
- ER для группы публикуется только по публикациям с полными данными:
  `(лайки + комментарии + репосты + сохранения) / просмотры × 100`.
  Выводятся **взвешенный ER** и отдельно медиана ER по публикациям,
  их нельзя подменять друг другом. Низкий ER не доказывает причину.
- Доля по числу слайдов рассчитывается по **проверенным** манифестам.
  Неполные / нескачанные карусели помечаются неразмеченными,
  не отбрасываются из исходного списка. Категория 9+ не теряется.
- Сравнения с аккаунтом всегда используют единый снимок профиля:
  новые значения из отдельного Bright Data сбора по посту не смешиваются
  со старым знаменателем. Для анализа одной ссылки нет сравнений
  с историей всего аккаунта.
- Один пост содержит максимум 24 слайда в текущем проверенном downloader;
  этот предел относится к размеру карусели, **не к числу публикаций**.
- Прерванные платные задачи не возобновляются автоматически после перезапуска.
- UI опрашивает состояние примерно раз в 1.7 секунды; процент на этапах
  ожидания внешнего провайдера отражает этап, а не прогноз ETA.
