# TikTok Carousel Studio

Отдельная студия Content Machine на **React 19 + TypeScript + Vite**.
Встроена в существующий Python-сервер, работает локально по
`http://127.0.0.1:8765/carousel-studio/`.

## Быстрый запуск на Windows

Из корня репозитория:

```powershell
git pull --ff-only origin feature/rtb-market-intelligence-20261030
.\RUN_CAROUSEL_STUDIO.ps1
```

Если PowerShell блокирует локальные скрипты:
```powershell
powershell -ExecutionPolicy Bypass -File .\RUN_CAROUSEL_STUDIO.ps1
```

Команда собирает React-приложение, проверяет Python-библиотеки, запускает
backend при необходимости и открывает Studio. При уже работающем сервере
достаточно обновить страницу.

## Возможности

- **Ссылка**: только реальная TikTok photo carousel (`/@handle/photo/id`).
- **Аккаунт**: получить **все обнаруженные в снимке Bright Data** карусели
  по профилю, без введённого студией ограничения 100 постов.
- Фото скачиваются через существующий `gallery-dl`; видео MP4 сознательно
  отбрасываются. Слайды хранятся как реальные изображения с проверкой SHA-256.
- Для каждого найденного поста запускается Gemini 3 Flash в OpenRouter
  с **полной каруселью как одним контекстом** и нейтральным промптом,
  без выдумывания техник по обычной позе.
- Bright Data собирает публичные цифры, числовые поля и производные
  отношения к просмотрам. Недоступные retention, watch time или среднее
  время на слайде остаются `null`, не угадываются.
- Обновляемый прогресс/логи, персистентная локальная SQLite, отдельный JSON
  и ZIP с оригиналами и результатами.
- Структурная статистика: 1–2, 3–5, 6–8, 9+ слайдов. В каждой группе
  количество и доля каруселей, медиана просмотров, ER, доля просмотров
  аккаунта и **индекс вклада** (доля просмотров / доля публикаций).
- Вложенные батчи по 10 публикаций, отсортированные по просмотрам от
  наибольших к наименьшим. В каждом батче доступны сравнительные метрики,
  описательные отклонения от медианы группы и переход к Gemini-анализу.
  Блок «Сравнение батча» показывает отношение медианных просмотров и
  взвешенного ER к группе, а также разницу в частоте хуков, CTA и
  интеграций продукта с *остальными* батчами той же длины. Для Gemini
  требуется не менее 3 валидных разметок с каждой стороны, для индекса
  просмотров — 3 наблюдения в батче и 5 в группе, для ER — 3 и 5
  соответственно. Если данных не хватает, показатель будет `null`.
- При запуске по **аккаунту** сохраняются публичные счётчики и обычных
  видео TikTok, чтобы сравнивать вклад каруселей со всем полученным
  снимком аккаунта. Обычные видео не скачиваются и не анализируются Gemini.
- Отдельный `group-analytics.json` доступен в UI, ZIP и SQLite.
  Для проверки знаменателя всех публикаций сохраняется
  `channel-snapshot-public-metrics.json`: публичные счётчики каждого
  возвращённого поста (включая обычные TikTok-видео), без загрузки их медиа.
- В архиве все фото, `manifest.json`, `metrics.json`, `analysis.json`,
  `full-analysis.json`, журнал и JPEG-входы Gemini. Логи можно скачать отдельно.

## Подключения

Ключи задаются только **на сервере**, никогда в React-форме.
Используются существующие настройки:
`CM_BRIGHTDATA_API_TOKEN`, `CM_BRIGHTDATA_METRICS_ENABLED=1`,
`CM_BRIGHTDATA_METRICS_RIGHTS_VERIFIED=1` и серверный OpenRouter ключ.

**Платные вызовы:** один запуск в UI разрешает необходимые запросы Bright Data
и Gemini. Количество каруселей не ограничено интерфейсом. Фактическое число,
стоимость и охват зависят от провайдера, лимитов аккаунта и количества слайдов.
Bright Data может вернуть не всю историческую ленту TikTok: интерфейс никогда
не считает неполный снимок полным архивом аккаунта.

Вариант с готовым snapshot_id без повторной оплаты источника пока не реализован.
Ошибки сетевого запроса на запуск Bright Data или после запуска Gemini не
повторяются автоматически, чтобы избежать двойного биллинга.

## Разработка

```powershell
python app.py
cd carousel-studio
npm install
npm run dev
```

Vite открывается на `http://127.0.0.1:5173/carousel-studio/`, запросы к
`/api` проксируются на локальный Python. Для production-сборки используйте
`npm run build`, выход находится в `site/carousel-studio/`.

## Ограничения

- Это **самостоятельная локальная SQLite**, а не подключение к основным таблицам
  PostgreSQL Marketing. Результаты каждой карусели хранятся одновременно
  как JSON на диске и в SQLite.
- Снимок профиля может не покрывать все исторические посты TikTok.
  Поэтому проценты вклада считаются только среди возвращённых публикаций.
  Если данные части публикаций недоступны, это отмечается в отчёте.
  Неизвестные просмотры не заменяются нулями. Если в снимке
  доступны просмотры не всех постов, доля известных просмотров
  отображается вместе с охватом; индекс относительного вклада
  скрывается до полного покрытия счётчика просмотров.
  Карточка карусели, не сопоставленная с фотопостом этого же снимка,
  не влияет на расчёт доли и ER аккаунта; её ID попадает в
  `unmatched_profile_item_ids`. Старые JSON без блока `comparison`
  остаются доступными в интерфейсе.
- ER для группы публикуется только по публикациям с полными данными:
  `(лайки + комментарии + репосты + сохранения) / просмотры × 100`.
  Выводятся **взвешенный ER** и отдельно медиана ER по публикациям,
  их нельзя подменять друг другом. Низкий ER не доказывает причину.
- Доля по числу слайдов рассчитывается по **проверенным** манифестам.
  Неполные / нескачанные карусели помечаются неразмеченными,
  не отбрасываются из исходного списка. Категория 9+ не теряется.
- Сравнения с аккаунтом всегда используют единый снимок профиля:
  новые значения из отдельного Bright Data сбора по посту не смешиваются
  со старым знаменателем. Для анализа одной ссылки нет сравнений
  с историей всего аккаунта.
- Один пост содержит максимум 24 слайда в текущем проверенном downloader;
  этот предел относится к размеру карусели, **не к числу публикаций**.
- Прерванные платные задачи не возобновляются автоматически после перезапуска.
- UI опрашивает состояние примерно раз в 1.7 секунды; процент на этапах
  ожидания внешнего провайдера отражает этап, а не прогноз ETA.
