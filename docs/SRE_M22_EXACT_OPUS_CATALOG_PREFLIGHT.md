## Current external reference and non-guarantees

OpenRouter advertises the exact model ID \`anthropic/claude-opus-5.5\`. Its public model endpoint API \`GET https://openrouter.ai/api/v1/models/anthropic/claude-opus-5.5/endpoints\` returns provider-specific \`status\`, \`tag\`, \`supported_parameters\`, context/output-token limits and **per-token pricing fields**. Consult [the public model page](https://openrouter.ai/anthropic/claude-opus-5.5) and [endpoints JSON](https://openrouter.ai/api/v1/models/anthropic/claude-opus-5.5/endpoints) for independent operator review. Public catalogs are time-varying. Example prices, provider count and status are **NOT hard-coded** to protect later quotes from stale data. A GET with no credentials does **not** prove the user's paid account has access to a provider endpoint.

As of the public model-page/API lookup on 2026-10-27, provider endpoints show \`response_format\` and in some cases \`structured_outputs\`; individual endpoint eligibility therefore must be tested **per pinned endpoint tag**, not inferred from the model family name. Provider pricing can differ by endpoint/region/service tier, and future routing may change. M22 does not silently substitute another model, pricing tier, endpoint or regional route.

## Files and entry points

**New:** \`intelligence/relevance/opus_catalog_preflight.py\`, \`tests/test_sre_opus_catalog_preflight.py\`. No SQL change.

- \`capture_exact_opus_catalog(timeout_seconds=5, opener=None, now=None)\`: an **optional, explicitly called** no-credentials read of **one fixed HTTPS URL**, using GET only. Redirect/cross-origin, non-200, non-JSON, invalid UTF-8/JSON, or more than 2MiB fails closed. No model-completion endpoint, webhook, price hold, financial side effect, automatic fallback URL or secret headers. Returns serializable immutable-input-style snapshot: \`schema_version\`, exact \`source_url\`, UTC \`captured_at\`, full public \`response\`, \`response_sha256=fingerprint(response)\`. The host may store such a snapshot in a trusted cache. **No background/polling/autofetch** in package import or normal offline preflight.
- \`preflight_exact_opus_catalog(snapshot, operator_expected_sha256=..., operator_endpoint_tag=..., operator_model_revision=..., requested_max_output_tokens=..., requested_input_proxy=..., now=..., max_age_seconds=900)\`: pure offline trusted-operator preflight. Requires independently authorized expected digest **not obtained merely from user-provided snapshot**; checks SHA, exact source URL/schema, UTC freshness <=15 minutes and <=30s future skew, with operator option to shorten TTL. A correctly self-hashed attacker-supplied snapshot is NOT independently trusted. Exact model only \`anthropic/claude-opus-5.5\`, immutable endpoint model revision \`anthropic/claude-opus-5.5-...\` without \`latest/current/auto/floating\`, **single** endpoint matching an operator-pinned tag (duplicate/missing denied), \`status==0\`, and both supported parameter labels \`response_format\` **and** \`structured_outputs\` mandatory. This intentionally excludes endpoints that support only one flag. Positive bounded context/max completion; proxy and output caps must fit the pinned endpoint. No automatic best/cheapest/alternative model/provider.
- Provider pricing must be present as finite, nonnegative **decimal strings** for \`prompt\`, \`completion\`, \`input_cache_read\`, \`input_cache_write\` and \`input_cache_write_1h\` (input/output token prices strictly positive). \`Decimal\`, not \`float\`, is used to validate exact transmitted prices and reject missing/nonfinite/fractional-int/negative/tiny-impossible values. Pricing is returned in USD/token **without** conversion, reserve, budget commitment or cost calculation. M23 must additionally pin actual account routing/usage and Decimal quote.
- The result \`sre-opus-5.5-preflight/v1\` includes exact model revision, provider endpoint tag/name, live model limits, exact decimal price fields, SHA of approved catalog and a compatible \`sre-opus-catalog-pin/v1\` for M20, plus explicit \`routing={"only":[tag],"allow_fallbacks":false}\`. The subsequent paid sender must truly enforce this policy; a JSON field alone cannot prevent provider rerouting.
- \`preflight_exact_opus_batch(m20_manifest, snapshot, ...)\`: verifies all exact M20 request/batch/leaf coverage and immutable hashes (reusing M21 transport integrity validation), then compares its model/version/catalog pin, input proxy bound, completion caps and batch SHA to this exact fresh M22 provider endpoint. A drifted model, a cheaper old endpoint, altered catalog pricing/SHA, missing JSON schema support, or expired snapshot **blocks M23**. Returns \`batch_preflight_sha256\`, anchored \`batch_manifest_sha256\`, \`catalog_preflight_sha256\`, endpoint tag, decimal price strings and request count. **It is not an actual quote.**
- Outputs are deliberately \`status="eligible_for_M23_quote_only"\`, \`quote_ready=false\`, \`dispatch_allowed=false\`, \`paid_calls=0\`, \`token_count_exact=false\`, \`requires_true_token_check=true\`, \`requires_live_catalog_revalidation=true\`. An M20 requested temperature of zero is **not** evidence the actual Opus endpoint accepts a \`temperature\` parameter: explicit \`temperature_send_supported\` is derived from provider capabilities; the later sender must omit unsupported parameters and reject unsupported mandatory controls. Likewise, public JSON capability flags do not guarantee every individual response is valid JSON; M21 still independently verifies the actual response.

## Data lineage and future authorization boundaries

C9 and D1 are **not** accepted from a client-supplied catalog snapshot. M22 validates only an operator catalog and M20 **already validated/pinned** project/C9/D1 batch transport. The user-facing API must separately authenticate the actor; the final send stage must recheck source D1 \`before_external_send\`, SRE M12/M14/M15 live worker fences, current exact endpoint availability/price, true token count against context limits, irreversible charge-intent dedup, SRE-specific consent and budget reservation. M22 performs NONE of those paid capabilities.

To avoid false claims, a pinned endpoint \`status=0\` in a fresh catalog is **catalog eligibility**, NOT confirmed real-time successful inference nor proof of access for the user's credentials. A saved snapshot is not a guaranteed provider reservation; it may be unavailable at dispatch time.
