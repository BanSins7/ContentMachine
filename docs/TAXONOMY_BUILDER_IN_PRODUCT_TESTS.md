# Taxonomy Builder / Test Studio в ContentMachine

**Статус:** реализация в PR #7. Это обычный интерфейс локального приложения `http://127.0.0.1:8765`, не GitHub Actions. Для работы необходимы локальный PostgreSQL, подтверждённый проект и ключ OpenRouter в настройках. Эта версия не делает автоматических многомодельных массовых запросов: каждый платный вызов запускается только вручную.

## Как сделать E2E или эксперимент с моделями

1. **Мои проекты → Новый проект**: заполни девять шагов и сохрани анкету. Ниша текущего Builder: Health & Fitness. В карточке **Проверь данные проекта** убедись, что факты о функциях и проблемах аудитории точны, подтверди ревизию.
2. **Pipeline Studio** → выбери одну из безопасных конфигураций:
   - **MiMo Flash → Opus 5.5 → Opus 5.5** (проверенная комбинация 10 фактов + 12 тем + Critic).
   - MiMo Flash на всех этапах.
   - Opus 5.5 на всех этапах.
   - Gemini 4 Argon на всех этапах (**эксперимент**).
   - MiMo Flash → Argon → Argon (**эксперимент**).
   - **Ручная настройка:** любая доступная из каталога OpenRouter модель на каждом этапе. Argon НЕ удалён и не устанавливается автоматически.
3. Для каждой стадии независимо доступны: точный идентификатор OpenRouter-модели, уровень или бюджет reasoning (только если это подтверждено каталогом), temperature (только если совместима), max output tokens и **версия промпта v1/v2**. Новые шаблоны используют `facts-v2`, `taxonomy-v2`, `critic-v2`. Рекомендованные максимумы: 5 600, 10 000 и **8 000**. Нажатие **Применить к черновику** НИЧЕГО не оплачивает.
4. **Сохранить черновик → Утвердить Pipeline**: фиксируется неизменяемая версия модели и параметров. При выборе изменённой модели/цены потребуется новая конфигурация.
5. **Смета**: ознакомься с оценкой низкого/ожидаемого/повышенного расхода; задай самостоятельно предельную сумму и отдельно разреши бюджет. Это согласие не отправляет запрос.
6. **Создать запуск**: новый run создаётся без оплаты. Затем нажимай **Выполнить следующий LLM-этап** **ровно один раз на каждый этап**:
   - Fact Extraction → прочитай дословные цитаты из анкеты, утверди/исправь/отклони факты и/или добавь человеческий факт.
   - Taxonomy Generation → получи проект категорий из утверждённых фактов.
   - Critic (если включён) → получи независимые замечания; модель **не изменяет** категории автоматически.
   - Human review → поправь название, определение, условия включения и исключения; затем **Утвердить и опубликовать Taxonomy**. База хранит неизменяемую версию и атомарно синхронизирует её с SRE.
7. **История тестов и Pipeline**: проектная история хранится в PostgreSQL и содержит модель каждой стадии, версию промпта, максимумы токенов, статусы, количество фактов/тем/замечаний, списания и неопределённый резерв. Можно вернуться к прежней попытке, посмотреть категории даже после сбоя Critic и экспортировать весь run в JSON.
8. Чтобы сравнить комбинации **на одном проекте**, открой **Новый тест с тем же Pipeline — новая смета**, утверди **новый бюджет**, начни новый run. Если хочешь другую комбинацию, вернись в Studio и утверди другую версию Pipeline перед новой сметой. Старые запуски остаются доступными. Никаких повторов после `uncertain` в том же run.

## Важные ограничения

- Эксперименты — реальные вызовы OpenRouter и могут расходовать средства. Автоматический запуск пяти сценариев или «retry» ранее оплаченного вызова не предусмотрен; производить сравнение можно последовательными ручными прогонами.
- Ключ OpenRouter хранится только на сервере локальной машины. В UI отображаются лишь безопасные provider HTTP статус/код/сообщение без заголовков, ключей и приватных метаданных. Сетевые ошибки, отсутствующая стоимость и тайм-ауты означают неизвестное списание; **не повторять** до сверки OpenRouter Activity.
- `max_output_tokens` включает внутренний reasoning. На Opus Critic с 2 000 токенов однажды получился `length`; 8 000 решило это на зафиксированном исследовании из 12 категорий, но не гарантирует успех на любой анкете.
- Публикация требует двух независимых человеческих утверждений; тестовая автоматическая симуляция human review из GitHub Actions не применяется к обычным проектам.
- Схема Taxonomy Generation для Gemini 4 Argon упрощена **только на транспортном уровне** из-за наблюдённой ошибки Google 400 INVALID_ARGUMENT; серверная валидация категорий не смягчена. Argon остался доступен, его E2E пока не подтверждён.
- Сервис не выполняет поиск или скачивание TikTok/Reels/Shorts на стадии Taxonomy Generation; категориальные примеры **иллюстративные**, без реальных показателей просмотров.
- Загруженные документы пока не включаются в промпт и смету, как видно в форме согласия.

### API, полезные для диагностики

- `GET /api/projects/{id}/taxonomy-builder/runs` — прочитать до 30 последних запусков (без оплаты).
- `GET /api/projects/{id}/taxonomy-builder/runs/{run_id}` — состояние, результаты, verified facts, topics и critic findings (без оплаты).
- `POST /api/projects/{id}/taxonomy-builder/runs` — создать run из отдельного действующего quote/consent (без оплаты).
- `POST /api/projects/{id}/taxonomy-builder/runs/{run_id}/advance` — **один** потенциально платный запрос.
- `POST /api/projects/{id}/taxonomy-builder/runs/{run_id}/facts/review` — человеческая проверка фактов.
- `POST /api/projects/{id}/taxonomy-builder/runs/{run_id}/topics/publish` — человеческое утверждение и публикация в SRE.

Операционные/архитектурные контракты: `docs/TAXONOMY_BUILDER_BLOCK6_RUNNER_V1.md`, `docs/TAXONOMY_BUILDER_BLOCK4_STUDIO_V1.md`.
