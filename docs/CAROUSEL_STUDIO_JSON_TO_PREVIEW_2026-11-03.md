# Carousel Studio · экспериментальная ветка

Ветка: feature/ai-avatar-carousel-studio-20261102.

Фото-генератор **убран из интерфейса**, но его Python API и старые unit-тесты сохранены для возможного возвращения. Ссылка в меню «Инструменты» ведёт на студию каруселей; старый адрес /avatar-studio.html перенаправляет на /carousel-studio.html.

## Цель и фактический статус

В браузере: загрузка одного JSON-файла или вставка JSON, готовый пример, необязательные фотографии (до 100 JPG/PNG/WebP), один скрин приложения (CTA), автоматический подбор по тегам, одно LLM-перефразирование **всей карусели**, сборка PNG слайдов на Canvas, галерея всех слайдов, стрелки/клавиши влево-вправо, единичный PNG и ZIP (включая manifest). Формат задаётся JSON: по умолчанию 1080×1350, поддерживается 1080×1920.

**Без загруженных фотографий** показываются явно маркированные градиентные заглушки. Это не генерация фото и не настоящие ассеты. Если CTA не загружен, вставляется заметная заглушка. ZIP можно выгрузить как черновик, но его нельзя считать финальным контентом.

**Без OpenRouter API Key:** при включённом LLM показывается исходный текст и предупреждение. Без LLM (галочка снята) текст исходный по выбору пользователя.

**Не реализовано пока:** постоянный фотобанк, сохранение рабочей сессии, анализ лиц/безопасных зон, автоматическое создание новых фото, batch из 100 каруселей, семантическая AI-проверка, публикация в соцсетях. QA проверяет наличие ассетов, повторы фотографий, длину текста и состояние LLM. Финальный визуальный и смысловой контроль нужен вручную.

## Пример JSON-инструкции

    {
      "carousel_id": "depuff_test_01",
      "avatar_id": "avatar_001",
      "format": "1080x1350",
      "language": "ru",
      "assets": {
        "photos": [
          {"id":"morning_sad","filename":"photo001.jpg","avatar_id":"avatar_001",
           "tags":["sad","puffy","morning"]},
          {"id":"cafe_happy","filename":"photo002.jpg","avatar_id":"avatar_001",
           "tags":["happy","cafe"]}
        ]
      },
      "slides": [
        {
          "id":"1",
          "role":"hook",
          "layout":"text_top",
          "image_query":{"required_tags":["sad","puffy"]},
          "text_blocks":[
            {"type":"headline","text":"Каждое утро моё лицо выглядело отёкшим","max_chars":85}
          ]
        },
        {
          "id":"2",
          "role":"cta",
          "layout":"text_top",
          "photo_tags":["happy","cafe"],
          "text":"Теперь я отслеживаю свой ежедневный уход в приложении",
          "cta":{"enabled":true,"type":"app_screenshot_overlay",
                 "position":"bottom_center","width_percent":43}
        }
      ]
    }

### Выбор фотографий

Требуемые теги: photo_tags или image_query.required_tags. Необязательные: optional_tags. Запрещённые: forbidden_tags. Требуемые теги должны совпасть; при отсутствии фотографии ставится **видимая заглушка**, а не неправильная эмоция.

Теги можно получить из имени файла sad__puffy__morning.jpg или описать в массиве assets.photos в JSON, сопоставляя точный filename и теги. Библиотека фотографий до отдельного фотобанка хранится только в открытой вкладке.

CTA: загрузить локальный скриншот в поле «Скрин приложения». При cta.enabled=true скрин накладывается на фото. width_percent ограничивается 20–80, position может быть bottom_center или top_center.

### LLM через OpenRouter

POST /api/carousel-studio/rewrite принимает массив слайдов id, texts, max_chars, role, модель, язык и необязательный временный ключ. Один платный запрос на карусель, без автоматических повторов. Система требует JSON-ответ с теми же ID, порядком и количеством текстовых блоков и соблюдением длины каждого. Промпт требует сохранять факты и не придумывать отзывы, результаты, гарантии, медицинские утверждения. **Автоматическая семантическая верификация пока не реализована.**

Ключ не записывается в JSON, результат ZIP или хранилище браузера. Если ключ на странице пустой, используется общий ключ Content Machine.
