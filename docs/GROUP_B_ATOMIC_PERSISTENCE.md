## Transaction and source gates
`persist_group_b_bundle(conn,manifest,assessment,candidates,packets,request_proofs,admission_verifier,plan?,registry?)` takes an already independently validated GB21 `UnifiedAssessment` plus typed domain candidates. It **recomputes** `validate_bundle` with current evidence packets/request proofs and injected attestor; a caller-supplied accepted boolean/report is not enough. It requires an independent `verify_bundle_persistence` callback **under a locked runtime run** that validates current project permissions, source rights/revocations, exact QDP inbox receipt, media bytes/GA result + policy version, provider request/prompt/model/paid attempt, worker authorization and full-source B5/B6/B7 attestors. Missing or failing callback: **DENY**, no rows.

All modifications are inside one `psycopg.Connection.transaction()` context (or nested caller-owned savepoint). The caller must commit any outer transaction. The function locks `group_b_runs` by project+run, holds current source and optional policy row SHARE locks to prevent rights-revocation TOCTOU, reads accepted `group_b_inbox`, checks exact video/source/content-kind/policy/GA snapshot/media-manifest/QDP run. Result `analysis_key=group-b-atomic/v1:<canonical SHA>` pins these plus all block proposal hashes, sampling policy and current topic registry. A second writer for the same run cannot create an alternate version; exact replay returns the existing analysis ID after consistency checks. A different input/version requires a **new Group B run** and analysis key.

Within that single transaction: create `content_b_analyses` parent (`pending`); insert B1 hooks+ordered parts, B2 format and B5 numeric metrics via static parameterized SQL; reuse GB16 B3 story for **video**, insert only source-verified `content_b_story_slides` for carousel B3 (SQL005 forbids `content_b_story_sampling` on carousels), plus GB17 B4 visual, GB18 B6 independent-detector subtitles, GB19 B7 0..N CTA, and GB20 B8 canonical topic atomic child persisters. Each specialist retains its own one-shot source/receipt/SQL readback gate. Child record counts and SQL005 read-only `content_b_story_patterns`/`content_b_cta_summary` are rechecked before any completed transition. The same transaction then updates all eight rows in `group_b_block_states`, the `group_b_runs.result_analysis_id` pointer and parent `state` + `analyzed_at`; any failure rolls back parent, children and status changes.

A `completed` write is allowed **only** when GB21 says all eight blocks individually `accepted`, its separate whole-bundle completion attestor says `can_complete=True`, and current source admission independently reaffirms full coverage. Unknown/needs_review modules have `partial` runtime state and **no fabricated SQL005 child rows**. The parent remains `partial`. A mixed/photo carousel cannot get B5/B6 video-only false results or falsely be completed; an explicit future not-applicable proof protocol will be required for all-block completion of carousel (GB21/22 intentionally conservative).

## SQL view contract and project isolation
`read_group_b_result(conn,project_id,run_id)` only reads the `content_b_analyses` referenced by `group_b_runs.result_analysis_id` for that exact project/run. It emits one analysis version, the existing `content_b_story_patterns` view, the SQL005 `content_b_cta_summary` nullable truth table and `group_b_block_states` statuses. No public read by bare `analysis_id`; other projects receive `None`. This is not an authorization boundary by itself—caller still must authenticate tenant/project access before supplying `project_id`.

## Immutable history and limitations
SQL005 preexisting triggers forbid changing a `completed` parent/children. The writer never updates a previously linked run to point to another analysis key and never UPSERTs an old child. If the original A/media/policy/human review result changes, downstream invalidation and new run orchestration belong to GB-MOD-24 (historical immutable versions retained). Authenticated humans can correct labels only through future GB-MOD-23 review revisions; not by rewriting a completed B row.
