# Исследование тем: новый единый интерфейс

С октября 2026 основной Taxonomy Builder внутри ContentMachine оформлен как
монохромное рабочее пространство с **одной текущей задачей**. Старый интерфейс
с большими таблицами и системными полями оставлен за необязательными «Деталями»;
все реальные платежи, API и серверные проверки по-прежнему действуют.

## Три шага без технических терминов

1. **Как проведём исследование:** выбери готовую комбинацию MiMo Flash → Opus
   5.5 → Opus 5.5 или настроь каждую модель. Gemini 4 Argon остаётся
   доступным для ручного выбора. «Тонкие настройки» раскрываются только по
   желанию. Применить шаблон/сохранить черновик не значит сделать платный запрос.
2. **Бюджет исследования:** главная сумма — ориентировочная общая стоимость;
   детализация сценариев и тарифов раскрывается по запросу. Отдельно подтверждается
   разрешённый бюджет конкретного запуска, затем старт. Повышенная оценка
   **не гарантирует максимальное списание**, поэтому есть резерв по модели.
3. **Темы для контента:** каждый платный LLM-этап запускается отдельно. Сначала
   пользователь по одной проверяет подтверждённые исходной анкетой факты,
   затем просматривает замечания Critic (если этап включён), затем решает судьбу
   каждой темы. Никаких автоматических paid retry и автоматических подтверждений.

## Режим карточек

- В центре **только одна карточка**. Названия и описание человеческим русским,
  поля анкетных данных — по смыслу, а не машинные JSON-ключи.
- **Одобрить / Отклонить** отмечают текущую карточку и показывают следующую.
  «Назад / Далее» листают карточки без изменения решения. Одобренное и
  отклонённое можно пересмотреть до финального подтверждения.
- **Факт:** основной смысл, кнопка «Показать исходную цитату» (оригинальная строка
  из анкеты) и «Изменить формулировку». Правка без «Одобрить» не является согласием.
- **Тема:** название, объяснение, что включать/исключать, примеры подходящих
  и неподходящих роликов. Кнопка раскрытия показывает факты, которыми
  обоснована тема, и замечания Critic именно по ней.
- **Critic:** отдельная очередь «Прочитано / Не применять» с пояснением проблемы
  и рекомендацией. Совет не применяется автоматически: необходимые правки в
  конкретной теме вносит человек самостоятельно.
- **Публикация:** кнопка появляется только после явного просмотра **каждой**
  категории, одобрения минимум двух тем (включая добавленную человеком)
  и дополнительного подтверждения. Утверждённая версия хранится в PostgreSQL/SRE.
- **Сохранность:** до финальной серверной проверки решения сохраняются
  как черновик **только в localStorage этого браузера** для конкретного запуска
  и состояния. Другой компьютер не увидит незавершённые решения. При
  повторном открытии текущего запуска черновик восстанавливается. Результат
  хранится в PostgreSQL только после явной отправки.
- **Навигация с клавиатуры**, когда курсор не в поле ввода:
  `A` — одобрить, `R` — отклонить, `←/→` — перейти к предыдущей/следующей.
  Кнопки имеют текстовые названия и доступны без горячих клавиш.

## Одно окно

- Во время работы открыто одно рабочее пространство в разделе проектов,
  без переходов по техническим подстраницам.
- История тестов, цены по этапам, ошибки провайдера, расход токенов и JSON
  находятся в **раскрываемых разделах** или боковых панелях.
- Можно открыть ранее оплаченный результат, даже если Critic позже завершился
  ошибкой. В таком случае карточки доступны **только для чтения**.
- Повторный тест создаёт отдельный запуск с новой сметой и разрешением;
  возврат к старому run не отправляет новые оплачиваемые запросы.

## Безопасность и проверка

В исходной логике сохранены строгая привязка фактов к цитатам анкеты,
минимум двух одобренных тем, проверка источников фактов, запрет повторного
платного запроса при uncertain, отдельное согласие на расходы и границы
одного запуска. UI никогда не маркирует весь Pipeline успешным только из-за
успешной генерации. Источник истины — PostgreSQL и ответ провайдера.

Тесты: `tests/test_taxonomy_run_ui.cjs`,
`tests/test_taxonomy_studio_ui.cjs` и PostgreSQL/Python suite CI.
Визуальный стиль: `site/taxonomy-workspace.css`, загружается через
локальный сервер ContentMachine. Отдельные изображения/шрифты/внешние
CDN не используются.
