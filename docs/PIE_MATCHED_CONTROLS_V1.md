# PIE-MOD-10 — Reproducible matched controls / comparison assembly

**Owner:** `feature/patterns-insights-full-module` only. **Contract:** `pie-matched-controls/v1`. **Status:** offline candidate-only. This does **not** authenticate UAE source rights, human approvals, causal comparability, production evidence or significance.

## Inputs and strict dependencies

`build_candidate_controls(snapshot, strata, outcome, policy)` requires **exact classes** `CandidateResearchSnapshot`, `CandidateStrata`, `CandidateOutcomePlan`, `MatchingPolicy`. All three frozen upstream artifacts must replay fully against one another, including exact project, producer observations, raw source revisions, strata key, low/high labels, neutral group, original exclusions and approved **claim**. Any missing, forged or incompatible upstream artifact fails closed. The function does no database reads, paid calls or downloads; it does **not** renew upstream authorizations.

`MatchingPolicy` has no implicit defaults: `policy_version`, `creator_rule`, `require_observed_niche`, `max_publication_gap_seconds`, `max_observation_gap_seconds`, `minimum_pairs`, `require_all_high_matched`. Time windows are closed limits in integer seconds. Inputs and versions are SHA-bound. No automatic success percentile, control threshold, treatment/cohort definition, author substitution or p-values.

**Creator control warning:** `same_creator` requires exact equal **observed `creator_key`** in the authenticated upstream row; `stratum_only_no_creator_control` allows different creators only with the prior common versioned stratum and explicitly records `uncontrolled_dimensions=['creator_identity', ...]`. The **creator cohort version is a taxonomy/definition version, not a proven shared creator cohort membership ID**; treating it as proof of a shared cohort would be wrong. `require_observed_niche=True` refuses missing topic/niche; a missing-niche match allowed by an explicit false setting is clearly labelled uncontrolled. Where a niche is present, the pinned PIE-MOD-08 stratum enforces an exact niche value. No fuzzy topic substitution.

## Deterministic maximum-cardinality pairing

Stage09's `high` is the case/contrast pool and `low` is the baseline/control pool; `neutral` is **not** eligible for either and remains recorded. All selected IDs must belong to the exact one pinned stratum from Stage08. The matching graph includes an edge only when the explicit creator rule holds and both the exact **predefined publication clock** gap and measurement schedule gap are within policy bounds. Both clocks are checked with timezone offsets, comparison in microseconds (avoid boundary rounding), `published_at <= observed_at` already enforced by the upstream row contract.

Edges are ordered by `(abs(publication_gap_us), abs(observation_gap_us), control_video_id)`, cases are processed in ascending canonical video ID, and deterministic **iterative augmenting paths** find **maximum cardinality** (not minimum total-cost matching, optimal covariate balance, a counterfactual or a causal estimate). The maximum graph size is 1,000 per arm and 100,000 qualified edges; exceed this and fail with `matching_capacity` instead of unbounded memory/compute.

Every matched control appears once; each case is matched at most once; row/snapshot hashes, original integer IDs, original explicit weights, creator rule and both time gaps are preserved. Outcomes, Group C magnitude, engagement, video labels, feature matrices and LLM opinions are **not** used to choose matches, preventing a trivial outcome-leakage path. The original selected/neutral/unselected-strata/exclusion totals are preserved and checked; unmatched high/low IDs remain visible with `no_eligible_control`, `control_capacity_exhausted`, `not_selected_for_pair`. There is no silent shrinkage of the research denominator. `minimum_pairs` must hold and `require_all_high_matched` can enforce complete case coverage. An unmatched group is not evidence of a negative result.

## Immutable replay, limits, and trust

The result `CandidateMatchedControls` is frozen and uses canonical sorted JSON `SHA256`, binds upstream snapshot, strata, outcome and matching policy hashes, plus all pairs, counts, identity, unknowns and lineage. `replay_candidate_controls(raw, digest, snapshot, strata, outcome)` rejects duplicate JSON keys, NaN/Infinity, malformed/oversized data, unsupported status/version, attacker-resealed pair/count/weight changes and mismatched upstream. It rebuilds exact pairs **from the source evidence** and compares complete payload, not just hash. Offline hashes do not authenticate producer or confirm current D1 source permissions.

`verified_live=False`, `ready_for_analysis=False`, `approved_live=False` permanently on this candidate type. The Stage09 injected `DesignApprovalAuthority` still represents only a mockable *claim*. Real research execution must separately prove current UAE exporter (UA-MOD-25), current SRE/QDP/A/B/C/D1 rights, independent authenticated reviewer and refresh authorization **before** analytics. Never interpret matched groups as proving causal uplift or balanced confounders. The next PIE-MOD-11 selects explicitly grounded features, then PIE-MOD-12 measures missingness/balance and PIE-MOD-14+ estimates descriptive effects under approved designs.
