# Content Machine — Stage 13: Product UI, User Control & Approval

Status: implemented on \`feature/project-source-intelligence-v1\`; keep PR draft until CI is green. Additive Stage13, no data migration. Stage12 backend and its immutable PostgreSQL constraints remain the authority.

## Explicit end-to-end user path

1. Open an existing project. Its Reference Registry, web/document/video ingestion and Evidence modules remain independently accessible and do not launch from Context Preview.
2. In **Project Context** click **Проверить проект и Evidence**. The read-only \`GET /context/draft\` displays profile revision, source/version IDs, analysis references, per-source grounded/reviewed counts, provenance/trust, rejected/pending Evidence, warnings and incomplete/excluded sources. No snapshot, budget, consent, run or model request is created.
3. Click **Создать неизменяемую версию** after confirming its SHA256. Server \`POST /context/build\` checks \`expected_context_sha256\` and either creates a new immutable snapshot or reuses the identical one.
4. Inspect the chosen historical snapshot. For **complete** context the UI offers \`approved\` or \`rejected\`. For incomplete context the UI offers **only** \`approved_partial\` or \`rejected\`, listing **every** excluded source ID. Explicit acknowledgment checkbox + confirmation are required to approve either mode, and the server enforces exact exclusions, fresh source hashes, project scope and one immutable decision. \`rejected\` is terminal for that snapshot. Users can compare two context versions by source, analysis, Evidence and profile diffs.
5. After approval, the **Использовать этот Context в RTB** action opens the existing Cost screen with the selected context ID (not a new RTB run). Users can also enter Context mode using the source-mode selector in the Cost screen. Neither transition creates a quote or makes a paid call.
6. Select an approved context and token budget (integer 100–8000). Click **Проверить точную выборку**. New read-only \`GET /api/projects/{pid}/taxonomy-builder/context-preview?context_id={uuid}&token_budget={int}\` calls exactly the same Stage12 \`context_material\` selector and checks current snapshot, individual Evidence approval, stored quote/locator pins, source integrity and Evidence eligibility. Returns immutable binding: context SHA, selection SHA, approval ID/decision, selected Evidence IDs and excluded IDs, plus the actual bounded, server-filtered quotations and citations. This endpoint cannot create a cost quote, consent, run or provider request. An unavailable/stale/unapproved/project-mismatched context fails closed.
7. Explicitly acknowledge the exact selection and, for partial contexts, the exclusions. Only then can users click **Создать смету по выбранному Context**. Immediately before POST, the UI re-reads the deterministic selection and compares all exact binding hashes/IDs/budget. The backend independently revalidates the same binding inside the quote transaction; the response is also checked against the expected binding. On mismatch the UI drops the preview/quote and asks for a new check. No automatic paid requests or retries.
8. Existing Cost UI displays contextual quote input scope instead of claiming that documents were excluded. User **separately** acknowledges uncertainty, sets a spending limit, approves budget and later starts each manual RTB stage. The new mode does not circumvent the single-consent/single-run rule or stage-specific cost reservations.
9. In Context-mode Human Fact Review, the existing one-card UI displays source type, trust label, evidence kind and citation. Fact alteration/addition is prohibited in the client **and server** unless independently re-grounded with a new Context version. Legacy questionnaire fact review, model configuration, taxonomic review and publication retain their previous behavior.

## Source-to-Evidence product workspace (Stage13.1–13.6, 13.9–13.10)

The existing nine-step Project Wizard opens the saved project details panel where all source modules are mounted: Reference Registry (add/archive/relabel), Research File Library (upload/replace/archive/restore/version download), document extraction (OCR, pagination, retry), web Sonnet 4.6 (quoted estimate and explicit payment approval), video acquisition (start/recheck/cancel/retry), transcription, Vision (local prep vs paid quote), Timeline Fusion and grounded Human Evidence Review (verify/approve/reject). Their existing safety/cost and retry contracts are preserved. No new job runs on display.

**Persisted consolidated activity:** \`GET /api/projects/{project_id}/source-activity\` is a strict read-only, project-scoped, paginated PostgreSQL view of \`project_sources\`, their current source-version IDs, evidence counts and latest 12 durable \`source_extraction_jobs\` per source, including stage, state, attempts/retries, billing state, error code and time. The Project Activity card loads on opening/reopening, updates manually and links to the specific source. A registered source without a version, queued task, partially processed asset or failed task is never labeled completed/ready. A source with verified stored Evidence is displayed as having Evidence, **not** as human-approved/true facts. Error code descriptions cover access, no speech, unsupported format, incomplete output, budget, stale source and media errors without masking original codes.

**PDF/DOCX:** Stage04 parser preview continues to fetch only bounded segments \`offset/limit\`, with page/table locator, extracted text, bounded table JSON and pagination. If the file is linked to a project source, the client lazily loads *current, explicitly human-approved* Stage10 Evidence and highlights only exact matching quotes using safe text nodes and \`<mark>\` (no HTML injection or reconstructed quotations). Missing citations do not fabricate highlights and missing Evidence does not hide the extracted document.

**MP4:** Stage06's verified local-acquisition job remains the only source of browser-playable assets. A read-only byte-range URL \`/api/projects/{pid}/sources/{sid}/video/jobs/{jid}/asset\` checks project, source, exact completed job, storage-manifest SHA/size, registered adapter archive root and local MP4 signature before transmitting bounded 4 MiB chunks via HTTP 206. Arbitrary client filesystem paths, incomplete/queued video and cross-project assets are never served. After reload the Source Video card GETs persisted jobs automatically and lets the user open MP4 metadata and the player on demand. Unified transcription / Fusion views already provide speech, OCR, visual descriptions and timestamped scenes, with full Fusion JSON export. If asset bytes are missing or corrupted, the user sees an unavailable error rather than an invented preview.

**UX reliability:** GET refresh is independent of localStorage/browser sessions; file/video/source/job provenance is server-bound. Buttons for mutating/paid actions retain explicit confirmation, local permission/size/format checks and the server's hard limits. Read-only inspection never auto-queues extraction or launches OpenRouter. Components support keyboard-focusable native controls and scale to mobile layouts.

## Browser reload, safe consent recovery and mode switching

On reopening an existing Cost page, the UI reads the **latest** immutable server quote. If it was created from `approved_project_context_v1`, it **never automatically replaces that quote with a questionnaire-only quote**. Instead, it opens the Context selector on the exact pinned `context_id` and `token_budget`; the user explicitly rechecks Evidence using the Stage12 read-only preflight. If the current approval, selected Evidence IDs, SHA256 or profile has changed, the preview fails closed and no old authorization is displayed as valid. If the preflight matches the stored quote exactly, the Cost panel restores the **same** quote ID and matching existing budget consent (if unrevoked and non-stale), without charging a provider, recording another consent, or POSTing another quote. The user may separately request a new quote; switching to legacy questionnaire from the mode selector intentionally triggers a new **free** quote but never a paid model call. Browser history and draft checkboxes do not override the server's immutable consent state.

## State machine and asynchronous races

- Legacy is the default quote mode. Selecting Context explicitly clears any old quote, consent and form approvals on that screen. Switching back to legacy explicitly calculates a new questionnaire-only quote. An existing contextual spending authorization remains a historical server record and is not mutated by UI changes.
- Changing context ID or token budget invalidates local preflight and previous quote instantly. Selection and quote network replies carry a sequence guard and are ignored if the user has switched project/context/mode in the meantime. Controls are disabled for active requests where appropriate.
- The \`tbContextAckSelection\` and \`tbContextAckPartial\` checkboxes are a user-facing gate, not a replacement for backend validation. Their state resets on any source/version/budget change.
- Historical Context remains viewable even if stale. **A new Context quote cannot use a stale snapshot**; historical already-authorized RTB runs replay the pinned Stage12 immutable provenance.
- No mutable writes are made on GET. Context snapshot approval, budget consent and RTB execution remain distinct irreversible actions with clear prompts.
- Untrusted text is rendered only by \`textContent\` in the UI, never by \`innerHTML\`, and never executed as script. The endpoint uses existing same-origin localhost Host protection; mutation requests need \`X-ContentMachine: 1\`. Sensitive model keys and raw media are not included in the preview.
- Published taxonomy and SRE integration remain Stage12's governed path. Stage13 does not invent or approve claims.

## Stage13 hardening — version-correct status and MP4 range transport

A source can have many immutable versions and jobs from prior versions. The unified activity API keeps historical jobs for audit, but each row now exposes `source_version_id` and `is_current_version`. The display state is calculated **only** from the jobs and Evidence of the active source version, and newest active-version jobs are prioritized inside the bounded list before historical rows. Uploading v2 cannot inherit v1's successful, failed, queued, or partial status. Historical job rows are explicitly labeled "прошлая версия" and continue to show attempts, charge state and errors. PostgreSQL integration tests exercise this with an actual v1→v2 transition.

The verified local MP4 endpoint uses HTTP 200 for a full no-Range GET, 206 for a bounded explicit/suffix range, with `Content-Range` only on partial responses, strict single-range parsing and finite decimal widths. The server streams fixed-size chunks instead of loading the MP4 in memory. Unsupported/multi/zero-length/oversized ranges fail closed with HTTP 416. File path, source job, immutable asset SHA/size and archive root are independently checked. HTTP tests cover the browser transport; direct resolver tests verify exact bytes, tampering and out-of-archive denial. No paid services are used.
