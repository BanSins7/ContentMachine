# Instagram Reels Top-100 — отдельный сервис Content Machine

## Запуск

Windows: START_INSTAGRAM_TOP100.bat из корня репозитория.
Адрес: http://127.0.0.1:8767/
React + TypeScript: instagram-top100-ui/
Backend: intelligence/instagram_top100/
CLI: python -m scripts.run_instagram_top100 --accounts "@user1,@user2" --scan-limit 500 --confirm-paid --confirm-rights

## Pipeline

1. Пользователь вставляет публичные usernames/URL. Поддерживается большой список (до 5000 в одном запуске).
2. По явно подтверждённой кнопке Bright Data Instagram Reels Discovery (dataset gd_lyclm20il4r5helnj) выполняет поиск с 1 ноября текущего года по сегодня, до заданного лимита 100–5000 публикаций на аккаунт. Используется type=discover_new, discover_by=url, num_of_posts, start_date/end_date.
3. Фильтрация требует подтверждённый Reel/video, автора или соавтора, дату, публичное количество просмотров; отсутствие данных не подменяется нулём.
4. Выбирается до 100 видео с наибольшим views на каждый профиль; не обещаем полноту истории аккаунта.
5. Для выбранных роликов вызывается существующий worker/local_worker.py::exact_download_job (подтверждение shortcode) с engine=off, без Whisper и платных LLM. Повторные файлы проверяются по source URL, shortcode и SHA-256.
6. Каждый шаг и snapshot_id сохраняются локально. При сбое повтор платного trigger при неизвестном результате запрещён.
7. После каждых **100 успешно скачанных и проверенных MP4** (по всем указанным аккаунтам суммарно) автоматически формируется отдельный ZIP. При завершении, отмене или частичном завершении оставшиеся 1–99 видео сохраняются в последний неполный ZIP. Исходные MP4 не удаляются и не перемещаются.
8. В каждом ZIP лежат MP4 в подпапках с именами аккаунтов, а также `manifest.json` (URL, дата, просмотры, SHA-256). Архивы создаются через временный файл с атомарной заменой. Созданные полные батчи переиспользуются после перезапуска; обновляется только изменившийся неполный батч.
9. В React появляются архивы с количеством файлов и кнопкой **«Скачать»**. ZIP передаётся сервером потоково и не загружается целиком в память.

## Папки

MP4: %USERPROFILE%\Downloads\InstagramArchive\<username>\<shortcode>.mp4
Метаданные: рядом с видео, shortcode.json
Состояния: %USERPROFILE%\Downloads\ContentMachineInstagramTop100\runs\<run_id>.json
Отдельные ZIP: %USERPROFILE%\Downloads\ContentMachineInstagramTop100\archives\<run_id>\batch_001.zip, batch_002.zip и далее.
Например: 100 MP4 = 1 ZIP; 230 MP4 = 3 ZIP (100 + 100 + 30).

## Настройка Bright Data прямо в UI

1. Запусти START_INSTAGRAM_TOP100.bat, открой http://127.0.0.1:8767/.
2. В поле **BRIGHT DATA API KEY** вставь API-ключ, нажми **Сохранить**.
3. После сохранения появится «Ключ сохранён». Значение ключа не возвращается в браузер и не хранится в localStorage; поле очищается. Замена ключа — вставить новый и снова сохранить.
4. Укажи публичные аккаунты, выбери глубину поиска и отметь оба подтверждения: возможная оплата Bright Data и права на хранение MP4. Только кнопка **«Начать сбор и скачивание»** отправляет платный запрос.
5. Действительность API-ключа проверяется реальным запросом к Bright Data после подтверждения запуска. Одно лишь сохранение ключа **не означает**, что провайдер проверил ключ.

Используется готовое локальное Windows-хранилище `studio_credentials.store`, защищённое Windows DPAPI (текущий пользователь). Ключ не записывается в React, job JSON, Git или незашифрованный .env. Разрешения на платный сбор относятся к *текущему запуску*; сохранение ключа не включает глобальные разрешения других инструментов Content Machine.

**Альтернатива:** по-прежнему можно указать `CM_BRIGHTDATA_API_TOKEN` через переменную среды или .env, но для этого отдельного сервиса это **не требуется**. Глобальные флаги `CM_BRIGHTDATA_METRICS_ENABLED` / `CM_BRIGHTDATA_METRICS_RIGHTS_VERIFIED` здесь также необязательны; они остаются для других инструментов проекта.

## Важные ограничения

- Источник может вернуть неполный список. Если публикаций с 1 ноября меньше 100, скачиваются только доступные и проверенные. Популярные Reels вне лимита scan_limit могут не попасть в результаты.
- Нет обхода приватных аккаунтов, авторизации, CAPTCHA, блокировок, rate limits.
- Несколько тысяч аккаунтов обрабатываются последовательно, а не одновременно.
- Возможен ручной resume по уже сохранённому snapshot_id, без повторного платного POST.
- Live Bright Data и Instagram MP4 в этой ветке не проверены. Обязательный тест на пользовательском ПК: 1 аккаунт + 1 MP4, затем тест 10 и 100.
- Нельзя считать отсутствие результатов подтверждением отсутствия публикаций.
- UI: cd instagram-top100-ui; npm install; npm run build. Dev UI: npm run dev (Vite 5174, backend 8767).


## Режим восстановления архивов

Кнопка **«Проверить ZIP»** в завершённом запуске запускает только упаковку уже скачанных файлов; новые платные Bright Data или Instagram-запросы при полностью завершённых аккаунтах не выполняются. При загрузке большого количества профилей архивы создаются из успешных MP4 по порядку их завершения, поэтому ошибка скачивания одного файла не блокирует накопление 100 других.

ZIP-экспорт не отправляет файлы в Haiku или другую модель: он предназначен для хранения и последующей пакетной обработки.
