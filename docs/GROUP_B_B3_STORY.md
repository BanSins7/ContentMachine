## Exact 26 semantic role taxonomy

For **sampled frames**, **semantic time intervals** and **carousel slides**, the same 26 SQL005 role names are allowed (exactly, case-sensitive):

`hook, context, problem, consequence, goal, myth, mistake, cause, explanation, fact, tip, step, demonstration, comparison, example, proof, testimonial, product_intro, product_demo, before_after, result, reveal, summary, offer, cta, other`.

There is **one** role per classified frame, interval or slide. Consecutive and nonconsecutive repeated roles are preserved. The proposal never sorts/deduplicates the semantic role sequence; video `story_pattern` is the exact original SQL005 view ordering by **interval_index**; carousel `story_pattern` is ordering by **slide_index**. A video technical Group A scene boundary does **not** establish a semantic interval. Frame, slide and interval analyses are distinct observations; the same meaning may occur at multiple levels without merging rows.

`before_after_phase` is NULL except for `role='before_after'`, where a proven phase may be `before`, `after` or `both`. In model JSON a missing phase is represented by empty string and becomes SQL NULL; if `before_after` phase is unknown then `needs_review=true`. `role='other'` always requires review by SQL005 constraint. Low confidence always requires review. `unknown_b3(plan,reason)` emits **zero role rows**, an honest noninferred status and reason; it never fabricates an `other` row to cover a missing observation.

## Source-first semantics and interval safety

`validate_b3_story(manifest,plan,response,receipt_verifier,delivered_visual_refs,boundary_verifier)` first **independently recomputes** `group-b-b3-sampling/v1` from the current exact Group A media manifest; a self-signed JSON SHA is insufficient. It accepts only real `sampled_frame` or `slide_ref` originals selected in the Stage15 sampling plan, which are tied to the original project/run/QDP/GA version/asset bytes/time/slide ordinal. It demands an explicit tuple of actual image refs delivered to the remote model, matching **all** matched plan refs, and an injected trusted `verify_b3_response()` that independently authenticates the provider response/request, approved budget attempt and delivered image bytes. A self-supplied `approved=true`, an opaque ref or a synthetic provider `VerifiedChatResponse` does not establish real provider trust. There is no production receipt verifier / paid dispatch wired in this stage, so synthetic CI fixtures are not claims of live semantic inference.

Video `frames` can only classify **matched** plan slots, using exactly their measured time and original sampled frame SHA. Carousel `slides` can only classify **matched** original slide ordinals; they have no fabricated video timestamps. A row may cite additional delivered visual refs but must cite its own original evidence ref. Unknown/missing/omitted-budget slots cannot receive semantic roles. If any matched slot lacks a role, if Stage15 coverage is incomplete, if a role has insufficient confidence, or if meaning intervals are absent/discontinuous, the proposal is `needs_review` (not fake `inferred`). If slide screen text is nonempty without a separate verified OCR witness, B3 rejects it rather than treating the vision model as an OCR source; visual_description is semantic commentary only on actually delivered pixels.

Video `intervals` are ordered, nonoverlapping **semantic** intervals. For each, start and end must be based on original observed sampled-frame timestamps, with independent proof refs at both ends; no extra interval is ever inserted across an unknown gap. To close an interval at verified original video end where there is no actual frame at the exact final millisecond, the last sampled frame must be at most **500ms** earlier and the end must be independently authenticated with `boundary_quality='known'`. `boundary_quality='known'` is never granted merely because the model or Group A technical scene cut says so; it requires trusted `verify_semantic_boundary` external attestation and exact frame-endpoint refs. `estimated` / `unknown` are always reviewable. A gap at the opening, middle or until **full measured video duration** is recorded explicitly; the 2fps/1fps sampling grid alone cannot prove all continuous frames were interpreted. The frame/interval roles may repeat, but their sources and time positions are not invented.

### Authenticated transcript/OCR as supplementary meaning evidence

Optional `text_packet` and `delivered_text_refs` allow a B3 frame, semantic interval or mixed-video slide to cite measured Group A `transcript_segment` / `ocr_span` *in addition to* its mandatory original visual ref. The validator must hash the actual untrusted UTF-8 data against the pinned A `content_sha256`, match exact QDP/GA result/video/content-kind/source-policy/delivery-state IDs, original media asset SHA and measured video-absolute time. Referenced frame text must contain the exact observed frame timestamp; referenced interval text must overlap the proposed interval; slide text must belong to the same original slide. Claimed delivery of any text ref must be authenticated by a **trusted four-argument provider verifier**; the historical three-argument verifier remains valid only when no text is claimed. Injected text or a transcript without a corresponding delivered visual proof can never establish a frame/slide role. A screen_text quote requires an exact substring of source-verified, actually delivered OCR for that same slide; otherwise screen_text is unavailable, not guessed from pixels. Delivered text/visual ref lists are retained in the versioned proposal for audit.

## Strict UNSENT request and budget gate

`B3_STORY_SCHEMA` uses the stage09-audited strict JSON subset with three arrays: `frames`, `intervals`, `slides`. Each object requires 26-role enum, valid phase string, confidence enum and source refs; interval additionally requires `boundary_quality`, start/end integer ms, slide includes optional empty visual/screen text as strings. The validator independently enforces original SQL005 cross-field rules and verifies model delivery; schema acceptance by itself is not authorization or evidence.

`prepare_b3_story_request` verifies the exact Stage15 sampling plan against its original manifest and an authentic `group-b-context/v1` **B3** packet from the same project/run/QDP/GA/media/policy version, then demands **every matched** sampled frame/slide be present in the context. The stage09 provider composer verifies actual PNG/JPEG/WEBP bytes SHA and model capability. The returned `B3PreparedRequest` contains a strict JSON-schema body with **trusted** `prompts/b3_story_v1.txt` (hash pinned), a body SHA, and the exact sampling-plan SHA. This is **not sent**; any provider execution, charge or logging requires later separately approved dispatch. A context with only 12 refs when the Stage15 plan has 60 cannot be falsely described as a full-model-sent storyboard. It is rejected and must be analyzed under a separately versioned partial-delivery protocol or reviewed. The current GB09/11 paid POST remains closed.

## SQL005 staging and ordered story view

`persist_b3_story(conn,analysis_id,manifest,plan,proposal,admission_verifier)` is an **opt-in, caller-transaction-owned one-shot** adapter. It does **not create a B analysis** and does **not** mark an entire analysis completed. The trusted host must first supply an existing `content_b_analyses` parent with `state='pending'|'partial'`, same video/source/source policy version/content type and authenticated `method_details` pins:
- `group_b_project_id`, `group_b_run_id`, `group_b_media_evidence_manifest_sha256`,
- `group_b_b3_sampling_plan_sha256`, `group_b_b3_story_proposal_sha256`.

It also requires a separate trusted `admission_verifier.verify_story_persistence()` returning literal True after **fresh** QDP/GA/source-policy/media-byte checks and authenticated model receipt. The module provides **no production admission implementation** and callers must never expose this as an untrusted HTTP callback. In tests, the admission verifier is clearly marked a fake, and a disposable PG17 DB is used.

In one transaction, the adapter locks the parent B analysis, refuses preexisting B3 sampling (new result requires a *new analysis_key*), inserts the exact six SQL005 sampling metadata fields with source/proposal/response hashes under `sampling_notes`, inserts one row per genuine classified frame/interval/slide into the original B3 tables, updates the parent analysis to `partial` (propagating review status), and queries original `content_b_story_patterns` to compare the **actual stored ordered** role sequence with the proposal. A conflict, source mismatch, missing host admission, incorrect order or view mismatch raises an error and must be rolled back by the enclosing transaction. This is a B3 component staging write, **not** a completed B1–B8 canonical output/approval (later GB-MOD-21/22).
