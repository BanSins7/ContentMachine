## Public synchronous operations (no daemon or background scheduler)

\`PostgreSQLGroupCWorker(policy=WorkerPolicy(...))\` exposes:

- \`claim(conn, project_id, worker_id)\`: independent autocommit connection; serialized global claim-budget via PostgreSQL advisory *transaction* lock, bounded per-project and global running counts. Reclaims expired project leases, then chooses one eligible due \`queued\` score job, joining its still-eligible run, using \`SELECT ... FOR UPDATE OF j SKIP LOCKED\`. Updates both job and run in **one transaction**; increments \`attempts\` + \`lease_generation\`, issues fresh random UUID \`lease_token\`, sets lease/heartbeat/worker and returns frozen \`WorkerLease\`. A busy job is skipped, a completed/cancelled/failed run never reopened, and a job from a different project never claimed. No sleeping/polling here.
- \`heartbeat(conn,lease)\`: conditional **token+worker+generation+project+run+video+unexpired** match. Extends lease for \`lease_seconds\` using PostgreSQL \`clock_timestamp()\`; a cancelled/expired/reclaimed/completed lease cannot be extended.
- \`recover_expired(conn,project_id)\`: bounded \`FOR UPDATE SKIP LOCKED\` on expired running jobs. Invalidate original token and increase fence generation. Retry after deterministic capped exponential delay if attempts remain, otherwise mark job+run failed. Never requeue terminal-complete work or revive an expired token.
- \`fail(conn,lease,error_code,retryable)\`: fenced failure transition. Strictly bounded \`attempts<max_attempts\`, exponential \`min(max_delay, base*2^(attempts-1))\`, \`available_at\` database timestamp and new generation on reschedule; terminal failures close run. A stale/cancelled lease cannot fail another worker's job.
- \`cancel(conn,project_id,job_id,reason_code)\`: explicit project-scoped cancellation of queued or running jobs, clearing owner/token and raising fence generation atomically with run cancellation; cannot cancel completed or failed jobs, repeated cancelled call is harmless.
- \`execute_score(conn,lease,review_request_id,approval_verifier,ports=None)\`: only score completion path; external trusted GC20 IAM is **mandatory**. It begins **one PostgreSQL SERIALIZABLE transaction**, locks exact job **FOR UPDATE** with matching live lease, then locks the run; validates pinned QDP run facts and metric source version. It invokes \`PostgreSQLC7Persistence.persist(transaction_managed=True)\` **inside that same outer transaction**, so authoritative D1/raw evidence, cohort/review/IAM verification, complete \`calculated_metrics\` row and immutable \`group_c_calculation_receipts\` are committed *together* with \`group_c_runs.state='completed'\`, exact calculated_metric_id/frozen cohort references and \`group_c_jobs.state='completed'\`. Rechecks real database lease deadline **after computation**; if expired, any error or lease cancellation occurs, the **whole transaction rolls back**, including C7. No other worker can steal a locked row until commit; an outdated generation cannot write. Uses the existing GC03 DB trigger ensuring run lineage matches the committed score. No guessed reviewer and no generic "preview" approval.
- \`run_once(...)\`: explicit single claim+attempt orchestration, no asynchronous loop. Retries only known transient SQLSTATE (e.g. \`40001\`/deadlock) and explicitly allowlisted dependency transients; fail-closed for bad signed approvals, source policy, metric definition and malformed data. A broken DB connection or lost lease fails noisily rather than falsely acknowledging completion.

\`WorkerPolicy\` is immutable, strongly bounds \`lease_seconds\`, global/project concurrency, recovery batch, and exponential retry window; no float-based scheduling or arbitrary unbounded loops. \`WorkerLease\`, \`WorkerFailure\`, \`WorkerCompletion\` are frozen, versioned receipts. Clock decisions use PostgreSQL \`clock_timestamp()\` rather than unsynchronized worker wall clocks; policies are user-supplied bounded local defaults, **not claims of reviewed global deployment configuration**.

### GC20 outer SERIALIZABLE mode

The preexisting \`PostgreSQLC7Persistence.persist\` normally begins its own SERIALIZABLE transaction, unchanged for stand-alone callers. GC21 provides \`transaction_managed=True\` only after starting and fencing its outer transaction. The GC20 writer verifies \`psycopg.pq.TransactionStatus.INTRANS\` **and** \`SHOW transaction_isolation='serializable'\` before taking this path, so it never silently starts an independent non-atomic score commit. All original review, peer/source/retention, exact Decimal C7/receipt/replay protections remain mandatory. A caller with access to this mode does not bypass IAM/authorization.

### Exactly-one durable commit, not exactly-once external execution

Multiple workers could attempt work at different lease generations after a crash; only a **current unexpired fenced lease** can commit the DB score and job completion. GC20's existing \`UNIQUE NULLS NOT DISTINCT\` C7 lineage, SHA certificate and all-field conflict checks make exact replay idempotent or explicitly fail conflicting mutation. The guarantee is **at most one committed canonical complete calculation for the approved version**, not a claim that CPU/IAM code was invoked once. Outbox notification, Analytics delivery, remote side effects and durable QDP ACK have their own contracts/steps and are not invoked.

An expired worker that runs beyond the lease deadline must roll back, even if it previously acquired the job lock; workers should call heartbeat on a **separate active connection before** entering long critical sections. While \`execute_score\` owns the row lock the heartbeat cannot acquire it concurrently. Production operator must choose lease duration longer than the worst-case bounded transaction duration or adopt a separate tested transactional keep-alive strategy; this implementation chooses fail-closed expiry rather than unsafe transparent extension.
