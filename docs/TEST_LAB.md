# Тестовый стенд ContentMachine

## Назначение

Вкладка «Тестовый стенд» в боковом меню основного интерфейса хранит сценарии поэтапной проверки. Каждый сценарий **ссылается на существующий проект из библиотеки по его project_id**. Это намеренно: если скопировать проект под другим ID, опубликованная таксономия, результаты RTB, данные Search Planner и история в PostgreSQL останутся привязанными к исходному проекту. Стенд не создаёт поддельные результаты и не дублирует DB-записи.

## Как проверить Otek AI

1. Запусти ContentMachine и открой `http://127.0.0.1:8765/#tools/test-lab`.
2. В «Проект из библиотеки» найди Otek AI / Отёк AI, если проект действительно уже создан на этом ПК.
3. Назови тест, выбери предел **Search Planner** и нажми «Сохранить тест».
4. В сохранённом сценарии нажми «Открыть выбранный этап» — откроется реальный рабочий экран Search Planner для **исходного project_id**, без повторного ввода анкеты.
5. После проверки увеличь «Расширить тест до этапа» на **Video Collector**; новый предел сохраняется на диске.
6. Для последующих проверок добавляй SRE, QDP, Group A/B/C, Unified Analytics, PIE по мере доступности работающих экранов и входных данных.

Открытие экрана — **не** запуск, подтверждение или завершение pipeline. Каждый платный, сетевой или публикующий шаг использует существующий экран своего модуля, текущие проверки доступа и отдельное действие пользователя. Поля «последний открытый экран» и «предел» — это метаданные навигации, а не оценка готовности.

## Постоянное хранение

Профили проектов сохраняются как прежде: Windows `%LOCALAPPDATA%\ContentMachineData\projects\<project_id>\project.json`, Linux/macOS `~/.contentmachine/projects/<project_id>/project.json`. Если задана `CM_PROJECTS_DIR`, она переопределяет корень.

Сценарии сохраняются отдельно в `<projects_root>/_test_lab/<scenario_id>.json`, атомарным переименованием файла и с optimistic locking по `revision`. При новом запуске приложения они читаются с диска заново. Исходные документы, профиль и результаты исследований не изменяются. Отсутствующий исходный проект помечается как недоступный, а не заменяется другим.

## Проверка

```powershell
python -m unittest discover -s tests -p test_test_lab.py -v
```

Встроенные тесты проверяют создание и повторное чтение сценария, расширение предела, возврат на прежний этап, конфликты ревизий, привязку к источнику, маршруты GET/POST, защиту локальных мутаций и выдачу UI-файлов.
