## Реализовано

Два обязательных явных флага `CM_SRE_M42_TEST_ONLY=1`, `CM_SRE_M42_DISPOSABLE=1`; отсутствие LIVE/QDP/Collector/provider-переменных; PostgreSQL >=17, отдельное имя БД `sre_m42_*`, exact `application_name=contentmachine-sre-m42-isolated`, non-superuser без CREATEDB/CREATEROLE/REPLICATION, только autocommit и созданный оператором уникальный marker `public.sre_m42_disposable_marker`. Любое несоответствие: fail closed ДО DML.
- Только `public.sre_m42_fixture_journal` **в изолированной тестовой БД**, без импортов платного транспорта, без M28 receipts/M30 results/M36 outbox и без внешней сети. Таблица создаётся после проверки marker; источник постоянный `synthetic_test_only_not_authenticated_provider`; поля `provider_authenticated=false`, `financial_settlement_authorized=false`, `exportable_to_live_consumers=false`, `paid_calls=0`. Невозможно использовать эти строки напрямую в M36: SQL M36 читает иные настоящие таблицы/вьюхи, не shadow fixture.

Никаких raw текстов/секретов/поддельных generation id в журнале — только канонический SHA-256 безопасного event и SHA источника. Детерминированный replay exact SHA; чужая или испорченная запись отвергается.
- `tests/test_sre_m42_fixture_isolation.py`: 9 dependency-free локальных unit-test методов, в том числе false entitlement/production role/database, missing marker, replay/tamper, отсутствие SQL DML перед проверкой и отсутствие network. ## Граница и порядок реального M42

Эта smoke-проба **не является** полноценным C9→D1→local rank-all→fake HTTP Opus→quote/consent/reserve→intent→synthetic receipt→M30→M32→M36 E2E. Она намеренно не создаёт ни одной строки с правами реального model-generated LIVE результата. Нельзя просто заменить payload настоящего M28 receipt на fake и сделать LIVE export green — это нарушит семантику аутентифицированного provider usage и бюджетные инварианты.

**Дальнейшая последовательность:** (1) независимая сверка schema_migrations/checksum для повреждённой `062_sre_live_opus_receipts.sql` с реальными установками, документированное forward-safe исправление и clean PG17; (2) реальный approved two-review C9+D1 rights fixture; (3) настоящее ONNX rank-all или явный BLOCKED при отсутствии model; (4) M20/M23/M24/M25/M26 исходный API workflow под контролем test-only runtime; (5) отдельно гарантированный fake-only M27 transport + simulated cost в отделённом ledger без придания M28 полномочий; (6) test-only verified pairs/review/outbox **не передавать** в обычный M36 live projection; (7) idempotent replay, revocation/purge, multi-label, RLS/fences и повторяемый PG17 E2E на точном кодовом SHA.

Эта стадия M42 остаётся `[ ]` до реального full flow и positive/negative PostgreSQL17 acceptance. M43–M47 остаются открыты. В production не выставлять тестовые флаги и не создавать `sre_m42_disposable_marker`. Любая настройка/деплой без подтверждённой тестовой изоляции должен отклоняться.
