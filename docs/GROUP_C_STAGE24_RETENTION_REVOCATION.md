## Threat / correctness invariant

A previously committed complete C7 is only a historical calculation. **\`score_status='complete'\` is not sufficient to expose it as valid**: source permission, policy version, TTL, most recent unfiltered raw snapshots, published metadata and every original frozen peer all can change or expire. Returning last-known values as current on source revocation or retention expiry violates Group C's source-rights contract. Do not mutate the historical complete row; it is certified by immutable signed human reviews, cohort freezes and \`group_c_calculation_receipts\`. Deleting that row directly is blocked by FK \`RESTRICT\` and append-only certificate/review triggers; do not disable triggers or bypass grants to pretend erasure succeeded.

## Scoped read API

\`PostgreSQLScoreRetention.read_current(conn, project_id, calculated_metric_id, ports=None)\`: requires autocommit PG connection, validates strict project/ID, starts one **REPEATABLE READ READ ONLY** transaction, finds exact project-owned score with joined immutable complete C7 certificate and originally completed run; same response \`score_not_found\` for absent/cross-project. Before revealing original Decimal \`breakout_score\` or certificate digest it performs these gates:

1. No durable \`group_c_score_invalidations\` entry for this score and no pending, verified \`group_c_erasure_requests\` request; either permanently denies otherwise.
2. Reuses local Group C D1 adapters (\`read_scoped_d1_bundle\`) for current project/video registry, source effective permission (\`can_store_metadata\`, \`can_store_metrics\`, \`can_derive_scores\`), exact pinned source_policy_version, source metadata current/not deleted, its \`expires_at\`, source and policy retention days, both original unmodified raw snapshots with valid, current status and TTL.
3. Reads **latest two unfiltered raw observations** (includes retracted, corrected, changed-version samples) and requires that they are the very same original snapshot pair; if not, reports \`retention_version_superseded\` without treating it as a source-rights revocation. A superseded result remains historical, not current, and is never silently substituted.
4. Checks pinned source metric definition, original \`group_c_cohort_freezes\` IDs against legacy \`comparison_cohorts\` purpose, project, target, source, policy and metric version. Uses existing GC11 \`_require_db_rights\` to independently recheck the **target and every frozen creator/prior/(optional) niche member snapshot + metadata** for current source rights/TTL.

A denial produces a frozen \`RetentionRead(state='unavailable',reason_code=original,error...)\` with **\`breakout_score=None\` and \`evidence_sha256=None\`**. A success alone returns \`state='valid_current'\`, typed original Decimal C7 and exact certificate hash. An infrastructure/SQL exception is not converted into 'valid'. This is the **required consumption boundary for later GC25 Analytics and GC26 HTTP APIs**. Direct \`SELECT calculated_metrics\` by privileged roles can still see historic raw C7: production DB roles must be restricted so consumers only use this gate. The module does not silently rewrite existing application roles or claim global RLS protection.

## Durable invalidation, not false rewriting

\`PostgreSQLScoreRetention.invalidate(...)\` is one **SERIALIZABLE** transaction, locks exact previously completed certified score and checks for a previously appended invalidation (same ID on exact replay). It re-runs the same live source/peer check. A still-current score is rejected (\`score_still_valid\`). A mere superseded raw version is rejected as a **permanent** invalidation (\`invalidation_not_proven\`) because a newer source observation is not proof that previous evidence was illegal; it remains unavailable as current. Only allowlisted source/policy TTL, metadata expiration/deletion, corrected/retracted original raw observation or frozen peer-rights failure can create an immutable invalidation record. The audit pins prior complete \`calculated_metric_id\`, original completed \`group_c_runs\`, source/metadata/snapshot/config/cohort certificate SHA and specific original failure code, with a canonical SHA-256 fingerprint. Both original score and approval decisions remain unchanged; it clears *only* undelivered outbox delivery states to \`failed\`, preserving immutable event payload (other pre-existing leased events cannot be retroactively recalled).

Migration 062 adds \`group_c_score_invalidations\` with one row per project/score, FK to certified completed Group C run, append-only trigger. It also guards later \`group_c_outbox\` inserts and transitions into \`leased/delivered\` after a recorded invalidation. **GC25's delivery worker must also call the live read gate immediately before external delivery** because source TTL and peer rights may expire before the audit invalidation has been materialized.

## Legally authorized deletion coordination: external blocker explicit

\`PostgreSQLScoreRetention.request_erasure(...)\` requires a canonical UUID \`authorization_event_id\`, reason \`legal_erasure_required\` / \`retention_erase_required\`, a signed assertion and injected real external \`ErasureAuthorityVerifier.verify_erasure_request(...)\` returning literal True. No embedded IAM bypass; synthetic test verifiers are confined to disposable QA. Creates one append-only \`group_c_erasure_requests\` record per project/score, binding authorizing event, SHA of signed assertion, reason and exact certified C7. Reusing the identical signed approval returns same ID; changing the event/basis/signature is rejected. **Immediately stops scope-aware read** (no Decimal or certificate SHA), marks undelivered outbox failed and prevents future outbox leasing/insertion.

**This stage does NOT physically remove bytes** from \`calculated_metrics\`, raw snapshots, frozen cohorts, signed reviews or backup archives. Existing migrations deliberately contain conflicting dependencies (\`ON DELETE RESTRICT\` and immutable-delete triggers). The returned and database state is exactly \`external_erasure_execution_required\`, not \`erased\`, and the request acts as a required coordination record for separately authorized dependency-aware legal erasure. An operator must perform provider-side deletion, remove/refactor references under a reviewed legal erasure contract, handle backup retention and verify completion; never bypass these constraints at runtime. This remains an explicit **BLOCKED_EXTERNAL** portion of physical-erasure work and therefore GC24 **is not fully production-ready**.
