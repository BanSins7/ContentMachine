0. ИЗМЕНЕНИЕ ЦЕЛЕВОЙ АРХИТЕКТУРЫ: SRE = САМОСТОЯТЕЛЬНЫЙ МОДУЛЬ
================================================================================

Ключевое требование владельца продукта: SRE хранится и развивается в СВОЕЙ ветке.
Когда модуль готов, он должен встраиваться в текущий main ОДНИМ обычным PR/merge,
не требуя переноса незакоммиченных файлов, коммитов из чужих feature-веток,
параллельной сборки Video Collector, QDP или Analytics, ручного копирования JSON
или изменения кода существующих модулей. Открытие/установка модуля НЕ запускает
платную модель, фоновые платные задачи или импорт/скрапинг.

Важная граница: "модуль полностью merge-ready" НЕ означает, что чужие НЕВЛИТЫЕ
Collector/QDP/Analytics уже образовали E2E. После самостоятельного merge SRE
функционален с RTB и D1 из main (с реальными DB записями и с тестовыми fixture);
внешние producers/consumers подключаются отдельными обновлениями ИХ модулей,
если они реализуют совместимые контракты. Сам SRE всегда готов принять такое
подключение через опубликованные порты. C v2 необязателен для поддержки C v1.

Три разных доказуемых статуса:
  MODULAR_READY: весь SRE код, БД, API, UI, local offline run, guarded LIVE run,
    feature flags, CI и безошибочный merge на текущий main; без внешних PR.
  LIVE_VERIFIED: дополнительно явный согласованный платный smoke Opus и ledger
    receipt на реальном разрешённом D1 видео, после отдельного consent.
  ECOSYSTEM_CONNECTED: отдельно реальные версии Collector→D1→SRE и
    SRE→QDP→Analytics совместимы, интеграционные тесты этих версий прошли.
Не выдавать MODULAR_READY за LIVE_VERIFIED или ECOSYSTEM_CONNECTED.

НЕИЗМЕНЯЕМЫЕ ПРОДУКТОВЫЕ УСЛОВИЯ ИЗ FIX:
1. Единственная production классифицирующая LLM: OpenRouter модель
   anthropic/claude-opus-5.5. При отсутствии этой точной модели — BLOCKED.
   НЕТ Fast LLM, альтернативной платной модели, fallback или cascade.
2. Локальная embedding-модель РАНЖИРУЕТ ВСЕ approved hypothesis leaves,
   не отбрасывает их по low similarity; allow_candidate_drop=false.
3. Видео принадлежит Discovery D1; SRE не создаёт второй video catalog.
   Hypothesis search query ≠ семантическое совпадение. Multi-label по всем leaves.
4. match/no_match/uncertain — семантические исходы. not_evaluated, blocked_rights,
   failed, uncertain_dispatch — технические состояния, НЕ LLM no_match.
5. Evidence привязано к точному D1 content_version/source_quote.
   Защита от выдуманных цитат обязательна, но literal quote ≠ gold accuracy.
6. Только утверждённая C9 v1 / human reviews / 11 полей контекста.
   Реальный C Corrector v2 — отдельно, после фактического утверждения.
7. GET/preview/quote/UI startup = 0 платных POST. Перед любым POST отдельные
   SRE quote, consent, Decimal reserve и committed dispatch intent.
   POST ВНЕ SQL транзакции; ambiguous timeout -> unknown, не blind retry.
8. LIVE export никогда не включает offline_fixture/legacy или отозванный контент.
   QDP не может быть исправлен "магически" за счёт одного SRE view:
   потребуется реализация live-gate самим QDP или его совместимый adapter.
9. Один запрос пользователя = один законченный MXX; без автоматического
   продолжения, слива main или разрешения расходов.
10. Ни одна работа в SRE не является разрешением коммитить в ветки Collector,
    QDP, Analytics, A/B, C. Контрактные kits можно подготовить в SRE; внедрение
    consumer-side изменений выполняет владелец соответствующего модуля.
