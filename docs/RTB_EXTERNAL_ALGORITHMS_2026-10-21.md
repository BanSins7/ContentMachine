# RTB — проверка точных алгоритмов других проектов (21 октября 2026)

## Термины и сравниваемая задача

ContentMachine RTB = **Research Taxonomy Builder** для стратегии короткого
контента, где исходные материалы — анкета собственника продукта + утверждённые
факты. Это НЕ то же самое, что полностью автоматическая кластеризация
тысяч уже собранных публикаций. Не смешивать тему исследования, факт
продукта, категорию классификации и фактически найденный тренд.

### 1. TopicGPT — NAACL 2024, открытые исходники

Paper: https://aclanthology.org/2024.naacl-long.164/
Code: https://github.com/chtmp223/topicgpt

**Точное опубликованное разбиение pipeline:**
- `generate_topic_lvl1`: генерация крупных интерпретируемых тем по
  исходным документам с prompt-инструкциями и seed topics.
- `generate_topic_lvl2`: отдельно строит более узкие дочерние темы на
  основе верхнего уровня и исходного корпуса.
- `refine_topics`: семантическая доработка (слияние близких, отсев
  редких и нерелевантных). Paper §3.1: Sentence-Transformer пары с
  cosine >= 0.5 для кандидатного отбора, LLM сравнивает группы примерно
  из пяти пар. Частота темы в корпусе — критерий для частотного
  удаления, но без корпуса этот критерий у нас неприменим.
- `assign_topics`: отдельное назначение темы документу с
  поддерживающей цитатой.
- `correct_topics`: повторная LLM-проверка/исправление назначений,
  приводящая их в соответствие со списком тем.

**Что взять:** разделить построение/уточнение дерева от его
последующего назначения роликам; хранить явные IDs источников и
отображать доказательства; давать человеку возможность менять
инструкции, темы и уровень ветвления. В RTB нельзя выдавать
`source_fact_ids` за семантическую верификацию цитаты: пока это лишь
ссылочная проверка, а смысл оценивается Opus и человеком.

### 2. BERTopic — корпусный topic modeling

Algorithm: https://maartengr.github.io/BERTopic/algorithm/algorithm.html
Hierarchy: https://github.com/MaartenGr/BERTopic/blob/master/docs/getting_started/hierarchicaltopics/hierarchicaltopics.md

**Точный default algorithm:**
1. sentence-transformer embeddings для текстов;
2. снижение размерности UMAP;
3. density clustering HDBSCAN с возможными outliers;
4. токенизация/CountVectorizer для кластеров;
5. class-based TF-IDF для характерных терминов каждого кластера;
6. дополнительное представление темы (например LLM) опционально.

Иерархия — не результат «LLM придумала три уровня»: BERTopic
рассчитывает похожесть c-TF-IDF представлений тем и объединяет их
в иерархическую кластеризацию (например scipy Ward linkage).
**Куда применить:** к реальному корпусу видео после Video Collector,
когда появляются тысячи названий, описаний, субтитров и меток.
На одной анкете BERTopic не даёт обоснованную полноту рыночных тем.

### 3. TaxoGen — KDD 2018, рекурсивная иерархия

Paper: https://arxiv.org/abs/1812.09551
Project: https://github.com/franticnerd/taxogen

**Механизм:** извлечь ключевые фразы, получить их embeddings, затем
рекурсивно разделять на подтемы через adaptive spherical clustering;
на разных уровнях перестраивать локальные embeddings, чтобы термины
оставались различимыми внутри своих дочерних веток. Каждая тема здесь
семантический кластер терминов, а не один произвольный термин.

**Что взять:** ветка нужна, если сохраняет самостоятельный смысл;
критерии дочернего уровня должны быть локальны для родительского
направления. Не переносить кластеризацию в анкетный RTB без корпуса.

### 4. TaxoExpan — 2020, расширение существующего дерева

Paper: https://arxiv.org/abs/2001.09522

**Механизм:** из существующей иерархии автоматически получить
обучающие пары <новое понятие, узел-якорь>; обучить
position-enhanced graph neural network предсказывать правильную
позицию нового понятия в дереве, учитывая локальный контекст соседей.
Это не просто просьба LLM придумать новые подпункты.

**Что взять:** новые найденные Video Collector направления следует
предлагать как **изменение конкретной ветки**, не переписывая
всю принятую таксономию; новые предложения проходят отдельное
человеческое утверждение.

### 5. Microsoft Content Understanding — hierarchical classification

Docs: https://learn.microsoft.com/en-us/azure/ai-services/content-understanding/concepts/classifier

У существующей категории может быть вложенный дополнительный
классификатор (`analyzerId`); нерелевантные документы явно
попадают в категорию `other`, чтобы систему не заставляли
принудительно назначать неверную категорию.

**Что взять для SRE/Video Collector:** разрешать
`unmatched/uncertain` с основанием вместо классификации любого
ролика в ближайшую гипотезу. Это downstream classification, не сам RTB.

## Где ContentMachine реализует наш алгоритм

**Уже в ветке PR #9:**
1. Анкета → `facts` с реальными цитатами → человеческое подтверждение.
2. Первый Opus 5.5 (`deep_first`) → направления, ветки, гипотезы
   с ID, `parent_id`, `source_fact_ids`, определения, rationale,
   include/exclude и видео-примеры.
3. Review №1 → explicit approve/reject/edit/merge/add; неизменяемое
   сохранение. Удалённые человеком ветки нельзя восстанавливать
   автоматически во втором проходе.
4. Второй Opus (`deep_second`) → доработка ТОЛЬКО после Review №1.
5. Quality Gate → coverage matrix по подтверждённым фактам,
   отсутствующие гипотезы под корнями, LLM-подозрения на дубли +
   консервативное лексическое сравнение, подсчёт новых направлений
   относительно предыдущего утверждённого/предложенного дерева.
6. Saturation → максимум 2 дополнительных *ручных оплачиваемых*
   вызова `deep_expand` (нет платного автоматического цикла).
7. Review №2 → повторная структурная/фактологическая проверка,
   immutable publication/SRE projection и интерактивное дерево.

### Отличия, требующие честных ограничений

- RTB **не** вычисляет качество или частотность тем на большом
  корпусе роликов; для этого нужен Video Collector и дополнительные
  методы TopicGPT/BERTopic.
- `source_fact_ids` и quote-подтверждение исходного факта —
  доказательство *происхождения*, а не корректности семантического
  вывода всей темы. Нужна человеческая проверка и, позднее, downstream
  SRE-валидация на реальных видео.
- Семантические дубли: Opus-модель предлагает конфликтующие пары,
  детерминированный фильтр ловит только явное лексическое перекрытие.
  `no duplicates` не равно математическому доказательству их отсутствия.
- Сатурация — **относительная**: после прохода нет новых существенных
  направлений в сравнении с предыдущей версией и нет серьёзных
  отмеченных пробелов. Глобальная полнота рынка не гарантируется.
- Не обещаем полную семантическую дедупликацию без независимого
  измерения на внешнем корпусе.

## Контрольные вопросы для последующей проверки на Video Collector

1. Сколько реальных видео соответствует каждому направлению?
2. Какие новые понятия регулярно появляются без подходящего parent?
3. Какова доля `unmatched` и сомнительных SRE-назначений?
4. Действительно ли два соседних узла образуют разные выборки?
5. Есть ли подтверждённые, но пустые направления без новых роликов?
6. Нужно ли предложить человеку новую версию Taxonomy v2 по
   результатам реальных данных? Никакой автоматической публикации.
