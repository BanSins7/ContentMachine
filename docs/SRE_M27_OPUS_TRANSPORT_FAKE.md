## Implementation

`intelligence/relevance/opus_transport.py` provides a typed, fail-closed transport boundary:

1. `build_pinned_opus_transport_envelope(m20_manifest, m26_record, catalog_snapshot, *, operator_expected_sha256, operator_endpoint_tag, operator_model_revision, now, timeout_seconds)` validates the COMPLETE sealed M20 batch, including every approved C9 hypothesis, the independently trusted M22 operator response SHA/model revision/endpoint tag, and one immutable M26 persisted request SHA, ordinal and budget reservation metadata. The passed M26 JSON is **not DB authority by itself**: callers must re-read it from the trusted project-scoped `read_committed_live_sre_opus_intent` on an idle autocommit DB connection. M26 and M22 are not spend permits.
2. Generates ONE chat completion payload for exact `anthropic/claude-opus-5.5` at the fixed HTTPS `https://openrouter.ai/api/v1/chat/completions` endpoint. No `models[]`, no auto/router model, no alternate destination. `provider.only=[operator_endpoint_tag]`, `allow_fallbacks=false`, `require_parameters=true`, `data_collection=deny`, `zdr=true`, `stream=false`, temperature zero, exact M20 `max_tokens`. A strict structural `response_format.json_schema` expresses M21's source-evidence reply shape, but never replaces M21 evidence verification.
3. All inputs and API envelopes have deterministic SHA pins, an exact reserved USD ceiling, bounded request bytes (256 KiB), bounded single-attempt timeout 5–90 seconds, a no-send-if-cancelled preflight and a prompt/secret-free hash-only telemetry helper. The fake/offline envelope has explicit false flags `exact_provider_tokens_verified`, `account_extra_fees_verified`, `dispatch_allowed`, `automatic_retry_allowed`; `paid_calls=0`. A preview does **not** assert that prompts were sent, truth or cost.
4. `FakeOpusTransport(scripted_response_by_request_sha).execute(envelope, cancelled=False)`: independent, injectable in-memory test double; **zero network, zero API secrets, zero DB mutation**. Requires exact predetermined response SHA, rejects cancellation/replay/missing script, returns untrusted raw model-like text for M21 with `receipt_verified=false`, `actual_charge_usd=null`. It does not invent a semantic label or treat fixture content as approved live classification.
5. A private `_one_https_post_for_future_gate` constructs exactly one `urllib.request.Request` over the fixed HTTPS URL with trust-host-provided Bearer secret and JSON content type. **Without an explicitly injected offline test opener it refuses to execute altogether**; the production CA-verified TLS/no-proxy/no-redirect opener must be safely enabled by a later M28/M29-reviewed gate, not by an environment variable. The injected offline opener validates one-attempt timeout, bounded JSON and strict fixed response URL; even HTTP 4xx/5xx, timeouts, dropped connections, wrong model or wrong media type are `provider_outcome_unknown` with no automatic retry. No secret, body or provider error text enters an exception.
6. `send_live_openrouter_opus` is explicitly *fail-closed under every input/ENV flag*. It never invokes the private wire implementation. M28 must implement authenticated provider response/cost receipts and atomic settlement; M29 must implement unknown-outcome recovery/one-shot send-claim. True exact billable tokens and account-specific fees/taxes must be preflighted, and prompt/worker rights revalidated just before any paid POST. Without these M27 deliberately does NOT expose a production send permission.

**Why the LIVE gate is closed:** M26 enforces one committed request intent per run. The actual system may contain multiple M20 requests (e.g., three C9 leaves). Sending any live POST now could create an uncaught expense, incomplete leaf coverage or unreconcilable unknown outcome. The transport wiring is a distinct deliverable; end-to-end paid production is not ready. No user ENV can override this safety property; a code change plus verified M28/M29 is required.
