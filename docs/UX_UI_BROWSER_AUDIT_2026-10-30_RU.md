# Content Machine: строгий аудит реального интерфейса

Дата: 30 октября 2026. Проверена реализация PR #47, затем повторно проверены исправления.

Оценки основаны на настоящих страницах в Chrome и пользовательских действиях.
Код использовался после обнаружения дефектов для их исправления, а не как доказательство качества.
Скриншоты — снимки настоящего UI. Ответы API, результаты моделей и статусы не подменялись.
Тестовые входные данные были вручную введены в проект «UX-аудит · питание».

по исходникам или mock-тестам было бы некорректно.

## Найдено и исправлено

1. **Библиотека: пустая карточка занимала около 340 px по высоте.**
   Заголовок, пояснение и кнопка были разнесены на большое расстояние.
   Снят унаследованный min-height и лишняя граница. Поиск и счётчик скрыты,
   когда проектов нет. После создания остаются компактные строки проектов.
2. **После сохранения анкеты общий project picker оставался пустым.**
   Экран RTB показывал созданный проект, а глобальная навигация могла запросить
   выбор проекта ещё раз. Контекст синхронизирован с фактическим project ID
   на экранах review / pipeline / cost / run. Проверено повторным созданием через UI.
3. **Активный шаг Search Planner визуально совпадал с неактивными.**
   В браузере у всех шести кнопок был фон rgb(248,250,252), хотя C9 имел aria-current.
   Исправлена специфичность стиля; активный шаг теперь имеет собственный фон,
   цвет и нижний маркер.
4. **Служебная шапка и авторизация вытесняли форму Search Planner.**
   До: header 246.34 px + authorization 237.38 px.
   После: header 121.67 px + свёрнутая authorization 47 px.
   Авторизация раскрывается штатным details; секрет не восстанавливается и не вводился.
   Второй одинаковый control очистки скрыт. Основная кнопка полностью видна:
   нижняя граница 927.27 px при высоте viewport 936 px.
5. **Экран проверки анкеты содержал вложенные карточки и пустую половину строки.**
   Сохранены все поля и действия. Теперь это ровные строки «поле / значение».
   Кнопки находятся выше нижней границы viewport; подтверждение остаётся отключённым
   по настоящему ответу backend о неподключённой PostgreSQL.
6. **Настройки меню были обрезаны нижней границей экрана.**
   Область этапов получила собственное прокручивание; инструменты и настройки
   остаются в нижней части меню. В проверенном viewport нижняя граница кнопки — 920 px.
7. **Прогресс анкеты оставался фиолетовым с почти чёрными будущими шагами.**
   Приведён к синему акценту и нейтральным незавершённым сегментам.
8. **Пустой workspace мог оставлять «Загружаем проекты…» после загрузки.**
   При отсутствии выбранного проекта loading-status завершается, управление обновлением восстанавливается.
9. **История показывала повторяющиеся англоязычные ошибки PostgreSQL.**
   Известные сообщения о неподключённой БД переведены; неизвестные ошибки не подменяются успехом.
   Уведомление SP local-only также отображается на русском.
10. **Нейтральное уведомление SP имело бледный цвет от старой тёмной темы.**
    Задан читаемый нейтральный цвет, важный status увеличен до 14 px.

Новые возможности pipeline, API, модели и автоматические подтверждения не добавлялись.

## Пройденные реальные сценарии

- Пустая библиотека → создание проекта через 9 шагов, включая пропуск необязательных полей.
- Заполнение анкеты → переход в библиотеку → перезагрузка → продолжение с того же шага.
- Проверка сохранности названия, ниши и цели после возврата назад.
- Создание проекта → автоматический выбор в общем picker → открытие RTB.
- Библиотека → поиск с пустым результатом → очистка фильтра → повторное открытие проекта.
- Повторное открытие сохранённого проекта после обычной перезагрузки страницы.
- Workspace → реальные сохранённые поля Research Foundation.
- Переходы RTB / Search Planner / QDP с сохранением выбранного проекта.
- Search Planner: C9 → Query Validation → C9; раскрытие / закрытие авторизации.
- Search Planner: ввод ru,en / PL → история → повторное открытие; значения сохранены.
- История: ошибки трёх настоящих источников → фильтр Research Taxonomy.
- Состояние отключённой кнопки подтверждения анкеты и создания QDP run при недоступных prerequisites.

Платные вызовы не запускались. Введённые значения — QA-входы, а не результаты AI.
Preview пересоздаёт своё одноразовое окружение при перезапуске; проверки сохранности
в этом аудите относятся к переходам и обычному reload, а не к долговечности этого контейнера.

## Реальная геометрия и контраст

Проверенный viewport: **1363×936 CSS px**. У браузерного API этой сессии нет
документированного изменения viewport. Размеры 1280×800 / 1440×900 / 1920×1080
здесь не заявляются проверенными и не имитировались CSS-масштабированием.

На проверенных workspace, анкете, библиотеке и SP горизонтальный overflow не обнаружен.
Отдельные измеренные пары:

| Элемент | Foreground / background | Контраст |
| --- | --- | ---: |
| Активный шаг SP | #1D4ED8 / #EAF0FF | 5.87:1 |
| Активный модуль в меню | #1D4ED8 / #EAF0FF | 5.87:1 |
| Ошибка SP | #B91C1C / #FFFFFF | 6.47:1 |

Это выборочные измерения отрисованного UI, не сертификат WCAG для всех состояний.

## Что остаётся

- **Реальный запуск моделей и чтение каждого AI-ответа не проверены.**
  Нет PostgreSQL и оплаченных сохранённых runs. Mock-ответы для визуальной оценки не использовались.
- Search Planner в remote preview возвращает настоящий local-only отказ. Проверка
  его платных и привилегированных операций требует штатного локального запуска.
- QDP по-прежнему содержит много служебных пояснений и пустых секций диагностики
  без выбранного run. Они не скрывались без проверки с настоящими данными.
- В QDP остаются отдельные английские backend-сообщения и технические термины.
- Длинные списки моделей, фактов и историй, очень длинные названия и три требуемых
  размера viewport нуждаются в отдельной проверке на машине с полноценными данными.

**Вывод:** визуальные и навигационные дефекты исправлены и повторно просмотрены.
Полная готовность инженерного инструмента по критериям исходной задачи не подтверждена.
