## Core distinctions

M31 measures **three non-interchangeable states**:
1. **Possible paid dispatch, UNKNOWN** — durable M26 intent without independent M28 generation receipt, held M25 USD remains `reserved_usd`; never assume zero charge or permit a retry. Critical alert `unknown_paid_outcome`.
2. **Provider invoice/accounted inference** — M28 authenticated generation read and receipt with actual `Decimal` provider inference USD. A paid generation can have a missing/malformed model answer; `confirmed_receipts`/USD are **not** category decisions. Alert `cost_without_complete_evidence` when receipts outnumber source-grounded M30 verified pairs.
3. **Verified classification** — M30 source-grounded per-`(item,C9 category)` proofs; distinguishes `match/no_match/uncertain`, blocked and not evaluated. A completed run requires the separate M30 every-item/batch/pair terminal gate. M31 never changes decisions/run states or publishes model text.

## API (trusted internal host only)

`intelligence/relevance/live_diagnostics.py`:

- `read_sre_live_diagnostics(conn,project,run_id,*,actor_id,actor_authorizer)`. Requires host-authenticated `read_sre_live_diagnostics` action, idle autocommit PG connection. One **REPEATABLE READ READ ONLY** transaction scans only project/run scoped SRE tables. Report includes original run state/cancel signal; expected/physical C9 items/pairs; verified receipts/evidence and explicitly unproven pairs; M15 technical attempt status/count (including pre-dispatch abandon); M26 pinned model ID, revision, catalog SHA256, request SHA256/ordinal (**never raw prompt**); M25 M28 numeric run reserve and confirmed inference USD, safely separate optional project-wide cap/held/spent/released; grouped append-only M25 finance and M29 reconciliation event counts; highest priority alert code. All USD values are exact `Decimal`, formatted to nine decimals; unexpected floats, negative ledger counters, forged evidence/proof cardinality and bad tenant boundaries fail closed. Neither account extra fees/taxes nor current D1 rights are claimed independently verified by this passive read. No raw source/transcript/key/model reasons/request body included.
- `read_sre_live_pair_trace(conn,project,run_id,item_id,category_key,...)`. Requires `trace_sre_live_pair`. Rebuilds original approved project/run/item C9 pair; returns safe item/category/technical state, original M26 request/intent/model/catalog digests and ordinal, matched M28 provider receipt/token/actual USD if a billed generation exists, and M30 proof/evidence digest **only** if verified. A paid but unclassified category is explicitly marked `provider_generation_accounted_but_classification_missing=true`. If response never arrived and no receipt was authenticated, cost remains NULL/unknown, never fabricated 0.
- `record_sre_live_diagnostic_checkpoint(conn,project,run_id,...)`. Requires `record_sre_diagnostic_checkpoint` host action; serializes via exclusive project workspace lock, **recomputes** the source report in the same transaction and writes only one fingerprinted source-derived snapshot. Unique `(project,run,snapshot_sha256)` makes an identical replay idempotent. The checkpoint does not give dispatch permission, alter original money or mark C9 results complete.

No public endpoint, secrets, free-form client telemetry JSON, or unsafe extra logging sink introduced. Avoid logging request objects, original D1 text, response text, credentials or traceback payloads at the HTTP boundary.

## SQL 065

`intelligence/migrations/065_sre_live_diagnostic_checkpoints.sql` adds `sre_live_diagnostic_checkpoints` with immutable project/run FK, trusted actor, fixed-only numeric counters for planned/physical pairs, proven decisions, M26 pending/total requests, M28 receipts, M25 held/inference-spent USD(24,9), M25/M29 event counts, fixed enum alert code, exact SHA256 and server-side `created_at`. **No raw prompts, model output, user content, URL or auth keys.**

SQL BEFORE INSERT recomputes every stored count/amount from authoritative M13/M15/M25/M26/M28/M29/M30 SRE tables under workspace synchronization and rejects forged metrics/alert priority. BEFORE UPDATE/DELETE always rejects, PUBLIC writes revoked, per-project time/alert indexes. These are **operational observations**, not separate financial authority; a snapshot hash itself is generated by the trusted Python host and its semantic integrity is not claimed to be an authenticated provider receipt. No existing 016/017 or 054–064 SQL was rewritten.

Alert priority (one most urgent code per snapshot): `unknown_paid_outcome` → `incomplete_pair_registry` → `cost_without_complete_evidence` → `blocked_rights_or_budget` → `incomplete_classification` → `no_alert`. Absence of alerts is NOT permission for paid POST and does not establish D1 source rights are still valid.
