## Authority and audited upstream schema

Audited main 001_foundation.sql (sources, metric_snapshots, media_assets), 002_discovery.sql (source_policy_versions, source_video_metadata, can_store_metadata), 003_performance_c.sql and 004_performance_c_integrity.sql (quality/source metric definitions and versioning), 006 SRE project membership and UAE 080/081/082 snapshot and invalidation tables. Reviewed legacy analytics/service.py _source/_assert_rights as an *informational* precedent, not copy-pasted code. The source of truth is current D1/project registry DB data, NOT UAE's persisted historical checked flags.

Rights required for a fully analyzed UAE publication are exactly can_store_metadata, can_analyze_media, can_store_metrics and can_derive_scores. Every one must be TRUE both in sources and in the currently active, reviewed source_policy_versions.permissions JSON. One missing, false, revoked or unknown flag is an outright denial; never substitute a previous version or a truthy string for true. There must be exactly one active reviewed policy for the exact pinned source/version, and current SRE project/video membership.

Retention is the **minimum** of the source retention_days and the specifically reviewed policy derived_retention_days (1..365). No omitted/zero/null/unspecified "infinite" default. The source's and policy's current grants also limit the attached evidence: exact pinned source_video_metadata (current/unremoved, matching policy), all pinned raw metric_snapshots (same source, exact versioned platform_post_views, exact quality/time/retention), and all pinned media_assets (same video/source, non-metadata-only explicit permission, valid sha256/kind/lifetime). Every evidence row's own explicit expires_at and its collected/observed/created/fetched time plus the effective retention window can shorten the resulting derived expiry. The earliest deadline wins; expiry at the boundary is already inaccessible.

## SourceRightsPins and source-backed port

SourceRightsPins(scope, metadata_id, metric_snapshot_ids, media_asset_ids) contains exact independently selected current IDs. No discovery of "any available" media or latest-good metric is allowed. A real authorized upstream caller must bind these pins to the verified current QDP A/B/C and D1 lineage; a self-constructed pin or a returned EvidenceRef is NOT producer authentication. Video/slideshow pins require exactly one media asset; photo/mixed carousel require at least two, and each kind is checked.

SourcePolicyCurrentReader(conn,pins,as_of=UTC) uses a caller-supplied project-authorized dict-row PostgreSQL connection; it does not connect on its own. capability() reports the actual available DB tables. check_current_rights(scope) re-reads the current source/policy, project membership and every pinned raw evidence row. It returns CurrentSourceRights with a derived expiry and deterministic SHA of the verified policy, permissions and exact evidence revision/IDs/retention, *not* a signed source permission token. read_current_policy(scope) implements the UAE source_policy reader port, returning a typed EvidenceRead.LOCATED only for a current verified read. This is still not an overall qualified UAE publication.

GuardedUAEReads(ports,rights) is a **separate mandatory safe read facade** for future intake/read/Patterns adapters. It rejects source-policy port mismatch and unsupported ports; for every peer read, it checks policy before and after the peer operation on the SAME connection/transaction and compares evidence SHA. Revocation, partial source evidence, changing policy, changed metric version, expired assets or lost project membership produce only MISSING or UNAVAILABLE with typed reasons; no partial payload is returned. It never converts a missing peer into LOCATED. authorize_intake(scope) checks all current rights; authorize_handoff(scope,snapshot_id) checks stored qualified identity/invalidation and current rights. authorize_snapshot(scope,snapshot_id) refuses any partial/blocked row, exact project/video/source/policy/run/SHA/content mismatches and an entry in UAE's immutable invalidation ledger. A previously qualified historical row is **not** proof of current authorization.

**Time and transaction limitation:** The caller must provide the actual current UTC as_of for each distinct request, not a cached startup clock. Calls must run against an authorized snapshot-consistent DB transaction; a long-lived REPEATABLE READ snapshot will not observe a policy change committed after that transaction begins. Begin a new transaction for every externally visible read or handoff and lock/serialize revocations where strict immediate cross-transaction guarantees are required. The double check detects changes **visible to that transaction**; it cannot defeat database MVCC or an expired clock reused by its caller. Historical UAEPorts.read is deliberately a low-level claim-only interface, not a publishable API. UA-MOD-12–19 must route real pipelines via GuardedUAEReads; this stage does not assert that handlers not yet built have been wired. Without real QDP/GA/GB/GC production approvals it must not emit qualified user-facing data.

## SQL candidate-only non-disclosure view

Forward-only migration 083 adds the SECURITY_BARRIER view uae_snapshot_current_rights_candidates, returning **ONLY** project_id, snapshot_id and video_id for historical qualified snapshot candidates. It dynamically refuses revoked source or policy, incomplete 4-right intersection, missing project membership, absent/invalid bounded retention config, expired/retracted or misversioned pinned metric snapshot, expired derived retention, UAE invalidation and incomplete checked evidence records. New revocations hide old qualified candidates without editing immutable history. No GRANT PUBLIC is issued.

**This view is NOT a complete authorized UAE read surface**: UAE 080 did not store per-snapshot metadata and media IDs, nor could its seven checked claims authenticate peer LIVE evidence. Using this view directly to expose analytics would be a security failure. Stage UA-MOD-19 must combine it with real project authentication, the full GuardedUAEReads source provenance and approved peer port readers, while enforcing proper database privileges; current snapshot base-table SELECT privileges must not be exposed through HTTP or external clients.

No shadow tables or alteration to source/Group A/B/C ownership. Stage 083 installs no workers, APIs, direct data access grants, scoring or automatic invalidation write triggers. Historical records remain immutable and an out-of-band source-policy revocation hides candidate IDs immediately **for new transactions**.
